# ARM STUDIO

> **로봇을 스크래치처럼 블록으로 코딩하는, 누구나 쓸 수 있는 로봇팔 제어 · 디지털 트윈 소프트웨어**

---

## 무엇인가

로봇팔을 움직이려면 보통 URDF를 읽고, ROS 노드를 띄우고, MoveIt 설정을 만지고, IK 솔버를 이해해야 합니다.
ARM STUDIO는 그 전부를 **브라우저에서 블록 몇 개를 잇는 일**로 바꿉니다.

자세를 블록으로 놓고, 블록 사이를 선으로 연결하면 그것이 곧 로봇의 동작입니다. 코드는 한 줄도 필요 없습니다.

```
[자세 A] ──[이동]── [그리퍼 닫기] ──[이동]── [자세 B] ──[그리퍼 열기]
```

시뮬레이션 3D 뷰와 실물 로봇이 같은 파이프라인을 공유하므로,
**화면에서 먼저 확인하고 실물로 내보내는** 디지털 트윈 워크플로가 그대로 성립합니다.

---

## 세 가지 정체성

### 교육용 로봇 코딩 툴

스크래치가 프로그래밍을 가르친 방식으로 로봇을 가르칩니다.
블록의 배치와 연결이 그대로 파이프라인이 되고, 학습자는 좌표계나 역기구학을 몰라도
"집어서 옮긴다"를 만들 수 있습니다.
실행 전 3D 미리보기가 있어 **실물을 부수지 않고 시행착오**할 수 있다는 점이 교육 현장에서 중요합니다.

### 범용 로봇 제어 툴

특정 로봇에 묶이지 않는 것이 설계 목표입니다.
**URDF를 드래그앤드롭하면 관절 구조를 자동으로 역산**하고,
base URDF는 환경변수 → 설정파일 → 폴더 자동탐색 순으로 찾습니다
(`_find_base_urdf()`, 주석에 *"하드코딩 없음"*).
로봇이 바뀌어도 툴은 그대로 쓰는 것을 지향합니다.

### 디지털 트윈 플랫폼

STL을 올려 작업 환경을 3D로 재현하고, fcl 충돌검사로 경로를 미리 검증합니다.
시뮬레이션이 먼저 도착해도 **실물의 도착을 기다렸다가** 다음 동작으로 넘어가므로,
화면과 실물이 어긋나지 않습니다.

## 핵심 아이디어: 「물컵 규칙」

이 프로젝트를 다른 로봇 SW와 구별짓는 단 하나의 제약입니다.

> **그리퍼 위에 물이 담긴 컵을 올려놓고, 한 방울도 쏟지 않는다.**

일반적인 IK 솔버는 목표 지점에 도달하기만 하면 중간 자세는 상관하지 않습니다.
하지만 물건을 나르는 로봇에게는 **경로 전체에서 수평이 유지되는 것**이 도달 정확도만큼 중요합니다.

이 제약이 시스템 전체를 관통합니다:

- **j2·j3·j4를 한 묶음으로 이동** — 세 관절 축이 같아 *합*이 기울기를 결정하므로, 하나씩 돌리면 중간에 합이 깨집니다
- **미세조정 자동 상쇄** — 사용자가 j3에 +5도를 주면 j4가 자동으로 −5도를 먹어 합을 0으로 유지
- **j5는 아예 잠금** — 돌리는 순간 무조건 기울어지므로 오프셋 자체를 금지
- **간편 이동은 4축 IK** — 솔버가 손목을 건드리지 못하도록 자유도를 제거한 별도 체인 사용
- 제공되는 5가지 이동 모드 이름에 **전부 `(수평유지)`** 가 붙습니다. 예외가 없습니다

관절 축 구성:

```
j1 = (0,0,1)  Z회전  ->  기울기 무관
j2,j3,j4 = (1,0,0)  같은 X축  ->  3개 조합으로 수평 유지 가능
j5 = (0,1,0)  Y축  ->  돌리면 무조건 기울어짐  =>  항상 고정
```

## 주요 기능

| 기능 | 설명 |
|---|---|
| **URDF 드래그앤드롭** | 파일을 올리면 관절각 자동 역산, 즉시 3D 미리보기 |
| **블록 파이프라인** | 자세 · 이동 · 그리퍼를 블록으로 연결해 동작 구성 |
| **텔레오퍼레이션 녹화** | 토크를 끄고 **손으로 직접 움직인 경로를 그대로 저장 · 재생** |
| **환경 · 충돌검사** | STL 장애물 등록, 계획 경로 사전 검증, 2D 경로맵 |
| **미세조정** | 3D는 정답을 유지한 채 실물만 보정 |
| **속도 제어** | 최대 4배속, 시뮬–실물 동기 실행 |
| **안전** | 관절 한계 EEPROM 기록, STOP 시 즉시 토크 OFF |

## 정밀도

공장 기본 게인으로는 정지 오차가 1.58°였습니다. 실측으로 튜닝해 **0.35°(진동 0)** 까지 낮췄습니다.

```
Kp32 / Kd32 / Ki0  ->  18 raw (1.58도)   <- 공장 기본값
Kp64 / Kd64 / Ki4  ->   4 raw (0.35도)   <- 채택
```

중력으로 남는 정상편차는 적분항(Ki)이 제거합니다.
현재 도달 허용치는 **6 raw ≒ 0.53° ≒ 엔드이펙터 3mm** 입니다.

## 현재 상태와 다음 단계

레퍼런스 로봇 한 대 위에서 **전체 워크플로가 끝까지 동작**합니다.
URDF 등록 → 자세 저장 → 파이프라인 구성 → 충돌검사 → 실물 실행까지 실제로 돌아갑니다.

"어떤 로봇이든"이라는 목표를 기준으로 보면, 아직 남은 일이 분명합니다:

- [ ] **`JOINTS=['j1'…'j6']` 6축 고정** — URDF에서 관절 수를 읽어오도록 일반화 필요
- [ ] **`J5_IDX=4` 상수** — "수평을 깨는 축"을 로봇 구조에서 자동 판별하도록 개선
- [ ] **`Robot` 클래스가 Feetech 전용** — Dynamixel · CAN · EtherCAT을 붙이려면 드라이버 인터페이스 분리 필요

즉 **기구학 · 경로계획 · UI는 이미 URDF 기반으로 범용**이고,
남은 것은 **축 개수 가정과 모터 드라이버 계층**입니다.
이 둘을 걷어내면 "다른 로봇도 움직인다"가 실현됩니다.

## 다음에 할 일 (예정)

### 무선 제어 — 2모드
지금은 노트북 USB 직결. 목표는 로봇 옆 드라이버 노드(미니PC/ESP32)가 모터를 잡고,
상위 컴퓨터(노트북/DGX Spark)가 무선으로 목표 관절값만 보내는 구조.
- **모드 1 · 와이파이**: 같은 공유기 안에서 WebSocket 으로 관절값 스트리밍.
  구현이 쉽고 ARM STUDIO 코드(IK/물컵 규칙)를 그대로 씀.
- **모드 2 · 비(非)와이파이**: 와이파이가 비효율적인 거리/환경용.
  후보: ESP-NOW(근거리 초저지연), BLE, LoRa(원거리 저속 - 명령 단위만), LTE 모뎀.
- 안전 원칙: 명령이 아니라 "목표 관절값"만 전송. 통신이 0.5초 끊기면
  드라이버 노드가 스스로 정지. 물컵 규칙 검증은 보내는 쪽에서 완료된 값만 나감.

### 실시간 음성 시뮬레이션 (DGX Spark)
말이 다 끝난 뒤가 아니라, **말하는 도중 즉시** 블록을 만들고 3D 미리보기를 시작.
- Whisper 스트리밍 전사 + LLM 을 동시에 상주 (Spark 램이 커서 가능)
- "분홍색 잡고 3번 목심 이동" 을 듣자마자 시뮬 시작 →
  이어서 "빨간색으로 가서..." 가 들리면 **내비게이션 재탐색처럼** 경로를 즉시 수정
- LLM 은 블록만 고른다 (관절값 직접 생성 금지 - 물컵 규칙/도달 판정은 ARM STUDIO 가 담당)
- 색/이름이 음성 지칭의 기본 키 → 설비마다 색을 쉽게 지정할 수 있게 해둠
