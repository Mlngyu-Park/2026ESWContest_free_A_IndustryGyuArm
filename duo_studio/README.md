# DUO STUDIO — 같은 블록으로 G1 · Spot

블록 프로그램 하나를 **로봇만 바꿔 끼워** 돌린다. 블록은 '무엇을' 만 말하고, '어떻게' 는 로봇마다 계산한다.
G1 STUDIO · SPOT STUDIO 를 합친 별개 프로젝트 (ARM STUDIO 파일은 건드리지 않음, 옛 두 스튜디오도 그대로 둠).

## 띄우기

```bash
./serve.sh            # → http://127.0.0.1:8772   (?robot=spot 이면 Spot 으로 시작, 마지막에 고른 로봇을 기억)
```
오른쪽 「로봇」 에서 고르면 프로그램은 그대로, 로봇만 바뀐다.

## 공통 블록 (`web/scene.js`)

| 블록 | G1 | Spot |
|---|---|---|
| 걷기 | 두 발, 도킹·바닥 물건을 돌아서 | 네 발 (빈손이면 팔을 먼저 접고) |
| 잡기 | 손을 세워 옆에서, 손가락마다 닿을 때까지 | 고정 턱에 붙이고 손가락을 닿을 때까지 |
| 놓기 | 든 물건 밑면이 면에 닿게 | 같음 |
| 자세: 서기 · 낮추기 | 쪼그려 앉기 (발 벌림) | 몸 낮추기 |
| 손 흔들기 | 왼손 | 집게를 들어 손목 흔들기 |
| 팔 거두기 | 오른팔 내려뜨리기 | 팔 접기 |
| 돌기 · 기다리기 | 같음 | 같음 |

- 장면도 하나: 도킹 = 기둥 + 윗판, **높이 0.50m** (두 로봇 다 닿는 높이), 큐브 5cm · 펜 지름 3.2cm 길이 12cm.
- 로봇과 상관없는 잘못(빈손으로 놓기, 두 개 잡기, 찬 자리, 든 채로 팔 거두기 …)은 `Scene.compile` 에서 먼저 → 두 로봇이 **같은 말로** 멈춘다.

## 구조

| 파일 | 내용 |
|---|---|
| `web/scene.js` | 장면(도킹·바닥 자리·물건) · 공통 블록 · 예제 · 블록 실행기 · 공통 오류 |
| `web/g1.js` + `g1kin.js` | G1: 블록 → 동작 (G1 STUDIO 에서 옮김) |
| `web/spot.js` + `spotkin.js` | Spot: 블록 → 동작 (SPOT STUDIO 에서 옮김) |
| `web/collide.js` · `base.js` | 부딪힘 계산 · 행렬/FK (공통) |
| `web/assets/{g1,spot}/` | 모델 · 겉모양 · 부딪힘 모양 (`make_shapes.py` 결과) |
| `web/app.js` | 화면 · 블록 판 · 로봇 고르기 |

새 로봇을 붙이려면: `Scene` 을 물려받아 `robotCompile(블록)` 과 `fk() · step() · pose` 를 채운다.

# 책꽂이 공정 (`books.html`, 11-02)

같은 블록·같은 공정을 **UR15 · Spot** 에 그대로 돌린다 (G1 은 다음 단계). 책과 책꽂이만 **물리 엔진(Rapier, Apache-2.0, `web/vendor/rapier`)** 으로 움직이고, 로봇은 지금처럼 계산으로 움직인다.

```bash
./serve.sh   # → http://127.0.0.1:8772/books.html   (?robot=spot)
node test_books.mjs [ur15|spot] [프로그램 이름 앞부분]
node test_disturb.mjs [ur15|spot] [장면 이름 앞부분]   # 실행 중에 책꽂이·책을 옮겨도 목표대로 끝나나
```

## 장면 (`web/shelf.js`)
- 책꽂이 1·2번이 ㄱ자로 가운데를 본다 (11-02 둘째: 셋 → 둘). 자리(x, y, 방향)는 `SHELVES` 를 그 자리에서 고쳐 옮긴다 (`resetShelves()` = 처음 자리). 아무 각도로 돌아도 되게 부딪힘 상자는 책꽂이 좌표 상자 + 행렬(`Ti`), 물리는 책꽂이 하나 = 고정 물체 하나. 칸 = 3단 × 3열, 이름 `책꽂이-칸` (1-1 = 맨 윗단 왼쪽 … 1-9 = 맨 아랫단 오른쪽).
- 칸: 너비 30 · 높이 32 · 깊이 30cm. 책(판): 두께 2.2 · 깊이 12 · 높이 14cm. 책 위 18cm·뒤 17cm 는 갈고리가 들어갈 자리. 칸 벽에서 4cm 는 비운다.
- 정렬대: 바닥에 누운 책을 걸쳐 놓고 다시 잡는 받침 (열린 쪽).

## 블록
| 블록 | 하는 일 |
|---|---|
| 책 옮기기 [칸] → [칸] [전부/한 권] | 칸의 책을 한 권씩 꺼내 다른 칸 책 옆에 꽂는다 |
| 바닥 책 줍기 → [칸] | 바닥에 누운 책을 모두 주워 칸에 꽂는다 |
| 기다리기 | |

## 공정 (`web/bookworld.js`, 로봇과 상관없이 같다)
1. **꺼내기** — 책 옆 틈을 그때 물리 장면에서 잰다.
   - 손가락이 들어가면 **바로 집기**.
   - 좁으면 **갈고리**: 손끝을 책 위로 넘겨 책 뒤로 내리고 앞으로 당겨 4cm 빼낸 뒤 튀어나온 앞부분을 집는다. (갈고리가 책 한 권 폭 안에 드는 로봇만. UR15 손가락 2.2cm 는 되고, Spot 집게 8.4cm 는 옆 책까지 걸려서 → 이유를 말하고 멈춘다)
   - 당긴 책이 칸에서 떨어지면 그 자리에서 멈춘다.
2. **꽂기** — 앞 4cm 만 남기고 넣기 → 놓기 → 닫은 손끝으로 앞면을 밀어 넣기 (손가락이 안 들어가는 좁은 자리). 옆 책이 밀리는 건 물리가 계산하고, 3mm 넘게 튀어나온 책은 한 번씩 밀어 정리한다.
3. **바닥 책** — 위에서 폭으로 집기 → 정렬대에 4.5cm 걸쳐 놓기 → 튀어나온 쪽을 두께로 다시 잡아 세우기 → 꽂기.
- 팔 길은 움직이기 전에 겉모양으로 미리 검사한다 (자유롭게 옮길 땐 책에서 4mm 이상, 0.012rad 마다). 다가가는 자세는 그다음 곧은 동작까지 되는 팔 모양으로 고른다. 이미 눌려 닿아 있는 것은 더 깊어지지만 않으면 된다.
- 잡기는 두 손가락이 다 책에 닿았을 때만 손에 붙인다.

## 로봇이 채우는 것
| | UR15 (`ur15b.js`) | Spot (`spotb.js`) |
|---|---|---|
| 몸 | 가운데 받침대(0.45m) 위 고정. 밑동(j1)은 양쪽 한 바퀴 — 덜 도는 쪽이 막히면 반대로 도는 답도 (`altWraps`) | 걸어서 칸 앞에 선다 — 아래 "Spot 이 가는 길" |
| 손 | 원본(도색용)에 집게가 없어 **직접 만든 평행 집게** (손가락 10cm, 벌림 0~17cm) | 고정 턱 + 손가락 하나 — 손가락을 넓은 틈 쪽으로, 닿을 때까지 닫아 책을 고정 턱에 붙인다 |
| 갈고리 | 세로로 세운 집게를 벌려 아래 손가락을 책 뒤로 | (집게가 넓어 꽉 찬 줄에선 안 함) |

| 프로그램 | UR15 | Spot |

| 1-1 전부 → 1-4 | 끝 28초 | 끝 75초 |
| 바닥 → 1-6 | 끝 22초 | 끝 52초 |

## Spot 이 가는 길 (`spotb.js`, 11-02 셋째)
1. **설 자리 후보** (`standCands`, 좋은 순): 칸 정면 (윗단 0.76m · 가운데 0.84m 조금 숙여 · 아랫단 1.0m 깊이 숙여) → 칸을 바라본 채 둘레로 10·20·30° → 옆으로 6~25cm → 5·10cm 뒤로. 바닥 책은 책을 보고 0.8m 둘레 16방향, 정렬대는 +x 쪽에서.
2. 후보마다 **몸이 닿나** (몸 직사각형 앞 0.62 · 뒤 0.565 · 옆 0.224 + 4cm, 바닥 끝 포함 · 바닥 책은 발 범위만) → **팔이 닿나** (`armReach`: 잠깐 그 자리에 세워 두고 칸의 책 앞부분을 집는 자세를 풀어 본다) → **길이 있나**.
3. **길 찾기** (`planRoute`): 바닥 10cm 칸 × 몸 방향 15°(24방향) 위의 가장 짧은 길(A*). 움직임은 그 방향 그대로 8방향 옆걸음 · 제자리 15° 돌기 (칸마다 몸 직사각형 검사 — 좁은 곳도 몸이 들어가면 지나간다). 걷기↔돌기를 바꿀 때 작은 벌점을 줘서 한 번에 몰아서 돈다. 다 찾으면 같은 방향 구간은 곧게 갈 수 있는 만큼 건너뛴다.
4. 걷기: 책꽂이 앞이면 먼저 몸째 뒤로 (든 책이 곧게 빠지게) → 팔 거두기 → 길 따라 옆걸음 · 돌기 → 몸 높이·숙임.
5. **막히면**: 무엇이 막았는지 말한다 ("1-1 앞 설 자리를 2번 책꽂이가 막고 있습니다" · "길이 없습니다 — 사이가 좁습니다" · "그 자리에서는 팔이 닿지 않습니다"). 화면(arm_studio_multi)에선 `world.waitOnBlock` 이라 끝내지 않고 기다렸다가, 사람이 장면을 바꾸면 다시 해 본다. 검사는 예전처럼 멈춘다.
- 검사 `test_disturb.mjs` 에 Spot 만: 사용자 로그 배치 (두 책꽂이를 왼쪽 멀리) · 좁은 통로 (마주 보게 1.6m) — 둘 다 통과.

## 케어 / 돈케어 — 실행 중에 사람이 옮겨도 (11-02 둘째)
- 블록은 칸 이름만 말한다 (좌표 없음). `planGoals()` 가 ▶ 순간 블록을 따라가 보고 "1-1 의 책 전부" 같은 말을 실제 책들로 묶어 책마다 최종 목표 칸을 정한다. 안 되는 블록은 시작 전에 알린다.
- **돈케어 = 책꽂이**: 옮겨도 되돌리지 않는다. 칸 이름으로 찾아간다.
- **케어 = 책**: 책 한 권 끝날 때마다, 그리고 `BookExec.interrupt()`(사람이 옮김) 때마다 책 전부를 다시 본다. 있어야 할 자리에 없는 책이 있으면 (지금 블록과 상관없어도) 그 책을 최종 목표 칸으로 옮긴 뒤 이어 간다.
  - 다시 짤 때는 먼저 손을 곧게 빼고(`aBackOff`), 놓아만 두고 안 민 책을 밀어 넣는다.
  - 바닥 책 줍기는 세 토막(바닥에서 집기 · 정렬대에 걸치기 · 다시 잡기)이라 어디서 멈췄든 이어 간다.
  - 되돌려 꽂을 때, 그 칸에 나중에 꺼낼 책이 있으면 그 옆에 손가락 틈 이상을 남긴다 (`slotY(cell, avoid)`).
- 검사 `test_disturb.mjs` — 6가지 장면 × UR15 · Spot 모두 통과 (끝까지 · 12권 모두 목표 칸 · 뚫음 0):
  - 책꽂이 1 옮기고 돌리기
  - 상관없는 책을 바닥에
  - 들고 가는 책을 빼서 바닥에
  - 책을 다른 칸에
  - 나중에 꺼낼 칸의 책을 바닥에
  - 책꽂이 2 를 멀리
- 끌어 옮기는 화면은 `../arm_studio_multi` (ARM STUDIO 복사판). 이 `books.html` 에는 끌어 옮기기가 없다.

## 건드린 책을 언제 고치나 — `world.fixMode` (11-02 넷째)
사용자가 고른다. 실행 중에 바꿔도 다음 일을 고를 때부터 따른다.

| 값 | 화면 이름 | 고치는 때 |
|---|---|---|
| `now` | 바로 고치기 | 하던 일을 멈추고 바로 (손에 든 책은 먼저 꽂는다 — 손이 비어야 다른 책을 잡는다) |
| `book` | 이 책 끝내고 | 지금 옮기는 책(`BookExec.cur`)을 마저 꽂은 뒤 |
| `block` | 이 블록 끝내고 | 지금 블록의 책을 다 옮긴 뒤 |
| `end` | 맨 끝에 | 블록을 모두 끝낸 뒤 마무리 단계에서 |

- 고칠 책이 여러 권이면 **가장 최근에 건드린 책부터** (`bk.touched` = 사람이 놓은 차례, 화면이 적는다). 손에 든 책은 어느 순서든 먼저 꽂는다 (손이 비어야 잡는다 — 정렬대에 잠깐 내려놓는 것보다 덜 돌아간다).
- 마무리 단계: 블록을 다 하면 `plan()` 을 한 번 더 돈다 (그때는 `now` 처럼). 제자리가 아닌 책이 남아 있으면 모두 고친다 — `end` 를 고른 경우 + 기다리기 블록 중에 건드린 책.
- 검사: `MODE=now|book|block|end node test_disturb.mjs …` (처음 값 `now`, 화면 처음 값은 `book`).
  - 11-02 UR15 "상관없는 책 9 를 바닥에" × 네 가지 모두 통과. 책 9 를 고친 때가 각각 던진 즉시 · 책 2 꽂은 뒤 · 1번 블록 끝난 뒤 · 블록 3개 끝난 뒤로 고른 대로였다.
  - 11-02 UR15 "두 권 던지기 (책 3 다음 책 9)" × 바로 · 이 책: 나중에 던진 책 9 부터 고침, 12권 모두 목표 · 뚫음 0.
  - 나머지 장면 × 네 가지 · Spot 은 아직 안 돌렸다.

## 블록 나무 — 블록 안이 어떻게 이루어졌나 (`blockTree()`, 11-02 넷째)
ARM STUDIO 원본의 `잡기 = [열기][하강][닫기][상승]` 처럼, 블록 한 줄 안에 무엇을 하는지 작은 칸으로 보이고 지금 하는 칸이 켜진다.
- 블록 → 책마다 ("전부" = 책1 · 책2 · 책3) → 단계 → 칸:

| 단계 | 칸 |
|---|---|
| 이동 → 칸 / 책 / 정렬대 (걷는 로봇만) | 물러나기 · 팔 거두기 · 걷기 · 몸 높이 |
| 잡기 (칸에서) | (갈고리) · 열기 · 넣기 · 닫기 · 빼기 |
| 잡기 (바닥에서) | 열기 · 하강 · 닫기 · 상승 |
| 다시 잡기 (정렬대) | (걸쳐 놓기) · 열기 · 감싸기 · 닫기 · 빼내기 |
| 놓기 | 넣기 · 열기 · 손 빼기 · 밀어 넣기 |

- 실행기는 동작 사이에 표지(`aLeaf` · `aChip`, 움직임 없음)를 끼워 지금 단계 · 칸을 `BookExec.at` 에 남기고, 지금 책은 `BookExec.node` 에 남긴다. 갈고리는 그때 옆 틈을 보고 정하므로, 정해지면 `BookExec.hook` 에 넣어 나무에 [갈고리] 칸이 생긴다 (실행 전에는 지금 옆 틈으로 미리 짐작).
- 고친 책은 그 블록 아래에 "⟲ 고치기 책N" 으로 남고, 아직 차례가 안 된 책은 고칠 자리에 "고치기 대기" 로 보인다.
- `now.next` = 다음에 할 단계 (이 책의 다음 단계 → 이 블록의 다음 책 → 다음 블록).

## 3D 미리 보기 — 최종 자리 · 걸을 길 (11-02 넷째)
- `goalGhosts(w, G, ex)`: 남은 걸음을 블록 차례대로 따라가며 꽂기와 같은 규칙(칸 안 책들 오른쪽에 4mm 띄워 붙이기)으로 칸마다 자리를 채워 본다 → 아직 목표에 없는 책의 최종 자리. 책꽂이 좌표로 두어 책꽂이를 옮기면 따라간다 (`ghostT`).
- `SpotBooks.previewRoute(legs)`: 블록 나무의 이동 단계를 차례로, 걸을 때와 같은 설 자리 후보 · 팔 닿기 · 길 찾기로 다리마다 길을 미리 찾는다. 몸은 안 움직인다. 지금 책 자리로 계산하므로 실제 걸음과 조금 다를 수 있다.
