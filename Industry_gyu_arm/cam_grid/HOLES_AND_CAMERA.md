# 목심 구멍 찾기 · 점 4개로 격자 맞추기 · 카메라 위치 계산

**박민규 · 2026-10-07 · 코드: `Industry_gyu_arm/cam_grid/grid.py`, `pose.py`**

사진 한 장에서 세 가지를 순서대로 한다.

```
사진
 │
 ├─ 1. 구멍(원) 찾기          → 화면 위 구멍 중심 수백 개 (픽셀)
 ├─ 2. 점 4개로 격자 맞추기    → 판 격자 ↔ 화면의 대응 (호모그래피 H)
 │                              → 판 900개 목심 자리를 전부 예측 + 검산
 └─ 3. 카메라 위치 계산        → H 에서 초점거리 · 카메라 위치 · 방향
```

신경망은 쓰지 않는다. 판이 **20 mm 간격 목심 격자**라는 사실 하나로 전부 계산한다.

---

## 1. 구멍(원) 찾기 — `grid.detect_holes`

판에는 **큰 구멍(목심)** 과 **작은 구멍(배수)** 이 섞여 있다. 큰 구멍만 쓴다.

### 1-1. 판 영역만 남기기

판은 파랑·흰색 타일이라, 색으로 판 영역을 먼저 정한다 (HSV, OpenCV 기준 H 0~180).

| 색 | 조건 |
|---|---|
| 파랑 | H 95~130, S > 80, V > 50 |
| 흰색 | S < 45, V > 140 |

두 영역을 합치고 닫힘 연산(9×9, 3번)으로 구멍 자리까지 메운 것이 판 영역이다. 판 밖(책상, 벽)의 어두운 점은 여기서 걸러진다.

### 1-2. 어두운 점 찾기

구멍은 주변보다 어둡다. 그래서 **"흐리게 만든 영상 − 원래 영상"** 을 계산한다.

```
dark = GaussianBlur(gray, σ=9) − gray
```

주변 평균보다 어두운 곳만 양수가 된다. 판 영역 안에서 `dark > 10` 인 곳을 남기고, 열림 연산(3×3)으로 잡티를 지운다.

### 1-3. 동그란 덩어리만

연결된 덩어리마다 다음을 본다.

| 조건 | 이유 |
|---|---|
| 가로/세로 비 0.5~2 | 길쭉한 그림자·틈 제외 |
| 면적 12 px 이상 | 잡티 제외 |
| (긴 변)² < 3 × 면적 | 속이 찬 동그라미 (속 빈 고리·선 제외) |

덩어리의 무게중심이 구멍 중심이다.

### 1-4. 큰 구멍만 고르기 — 크기 기준을 고정하지 않는다

카메라 거리에 따라 구멍 크기가 바뀌므로 "몇 px 이상" 같은 고정값은 쓰지 않는다.

**처음 (격자를 모를 때): 면적 분포를 두 무리로 나눈다 (오츠 방식)**

면적의 로그값 분포에서 두 무리가 가장 잘 갈리는 문턱을 찾아, 큰 무리만 쓴다.

```
실측 면적 분포 (사진 1095×1494)
  작은 구멍:  15 ~ 60 px²     ← 배수 구멍
  골짜기:     77 ~ 107 px²
  큰 구멍:   150 ~ 700 px²    ← 목심
```

**격자를 알고 나면: 격자 간격에 비례시킨다**

```
큰 구멍 면적 ≈ 0.107 × (격자 간격 px)²       ← 실측 445개 중앙값
허용 범위     0.35 ~ 2.8 배
```

화면 가운데에서 격자 한 칸이 몇 px 인지는 H 로 계산한다 (`grid.pitch_of`).

## 2. 점 4개로 격자 맞추기 — `grid.fit_full`, `grid.grow`

### 2-1. 원리: 점 4개면 판 전체가 정해진다

평평한 판을 카메라로 찍으면, 판 위의 점 (i, j) 와 화면 위의 점 (u, v) 는 **호모그래피** H(3×3 행렬)로 이어진다.

```
[u·w]       [i]
[v·w] = H · [j]          (i, j) = 목심 칸 번호,  (u, v) = 화면 픽셀
[ w ]       [1]
```

H 는 9개 값 중 비율만 의미가 있어 **자유도가 8** 이다. 점 하나가 식 2개(u, v)를 주므로 **점 4개면 H 가 정해진다.**

H 를 알면 판의 **900개 목심이 화면 어디에 찍혀야 하는지 전부 계산**된다. 가려진 구멍, 화면 밖 구멍까지 예측할 수 있다.

### 2-2. 첫 점 4개 고르기

아무 구멍이나 4개 고르면 안 된다. **격자의 한 칸(정사각형 네 꼭짓점)** 이어야 한다.

1. **격자 방향 찾기** (`grid._basis`)
   - 구멍마다 가까운 이웃 5개로 가는 벡터를 모은다
   - 이웃 거리 중앙값의 0.7~1.4배인 것만 쓴다 (한 칸짜리 이웃)
   - 벡터 각도를 180° 주기로 히스토그램 → 가장 높은 봉우리 a₁, 그로부터 90°±12° 안의 봉우리 a₂
   - 각 방향 ±7° 안 벡터들의 평균 = **기저벡터 e₁, e₂** (화면에서 한 칸이 가는 방향과 길이)

2. **점 4개 만들기**: 구멍 하나 o 를 원점으로 놓고

```
격자 (0,0) (1,0) (0,1) (1,1)
   ↕     ↕     ↕     ↕
화면   o   o+e₁  o+e₂  o+e₁+e₂
```

이 4쌍으로 첫 H 를 바로 푼다 (`cv2.getPerspectiveTransform`).

### 2-3. 넓혀 가며 다듬기 (`grow`)

첫 H 는 한 칸 근처에서만 정확하고, 원근 때문에 멀리 갈수록 어긋난다. 그래서 반복한다.

```
반복 (4~6번):
  ① H⁻¹ 로 찾은 구멍 전부를 격자 좌표로 바꾼다     (i, j) = H⁻¹ · (u, v)
  ② 반올림한 정수 칸과의 거리가 0.3칸 안이면 '맞음'
  ③ 맞은 구멍 전부로 H 를 다시 푼다                 cv2.findHomography(RANSAC, 2.5 px)
```

한 번 돌 때마다 맞는 구멍이 늘고, H 는 판 전체에서 정확해진다.

### 2-4. 가장 좋은 격자 고르기

원점 후보 구멍을 60개 골라 하나씩 시험해서 (`fit_full(tries=60)`), **맞는 구멍이 가장 많은 H** 를 고른다.

### 2-5. 검산 — 예측한 자리에 진짜 구멍이 있나

| 결과 | 뜻 |
|---|---|
| 예측 자리에 실제 구멍이 있다 | 계산이 맞다 |
| 예측 자리가 비어 있다 | 계산이 틀렸거나, 물건이 가리고 있다 |
| 재투영 오차가 작다 | H 가 정확하다 |

**실측 (사진 한 장, 1095×1494)**

| 항목 | 값 |
|---|---|
| 찾은 큰 구멍 | 447개 |
| 한 격자에 맞음 | **419개 (94%)** |
| 재투영 오차 중앙값 | 1.3 px |

맞지 않은 6% 는 판 밖 잡티와 이음새 근처의 오검출이다.

### 2-6. 한 칸 밀림은 구멍만으로 못 잡는다 → 체크무늬로 잡는다

구멍은 전부 똑같이 생겼다. 그래서 격자가 **정확히 한 칸 밀려도** 예측 자리에 구멍이 다 있어 검산을 통과한다. 이건 **파랑·흰 체크무늬(10칸 주기)** 로 잡는다. 칸 가운데 (i+0.5, j+0.5) 의 색을 읽어 10칸마다 색이 바뀌는 위치를 찾으면, 타일 경계가 정해져 칸 번호가 확정된다.

```
실측: j 방향으로 읽은 색   BBBBBBBBBB WWWWWWWWWWWWWWWWWWWW
                          ← 10칸 → (타일 한 장 = 10×10 칸 확인)
```

## 3. 카메라 위치 계산 — `pose.py`

H 안에는 **카메라의 렌즈(초점거리)와 위치·방향**이 함께 들어 있다. 이걸 꺼낸다.

### 3-1. 판 좌표계

| 축 | 뜻 |
|---|---|
| 원점 | 판 30×30 의 첫 목심 |
| x | i 방향 (칸 번호가 커지는 쪽) |
| y | j 방향 |
| z | 판에서 위로 |
| 단위 | m (한 칸 = 0.020 m) |

### 3-2. 초점거리 — 렌즈 값을 몰라도 영상에서 구한다 (`focal_from_H`)

휴대폰 영상처럼 렌즈 값을 모를 때 쓴다. 카메라 행렬을

```
    [f  0  cx]
K = [0  f  cy]        cx, cy = 화면 가운데,  가로세로 같은 f 로 가정
    [0  0   1]
```

로 두면, 판이 가진 두 사실이 f 를 정해 준다.

1. **격자는 직각이다** → 판의 x 방향과 y 방향이 3D 에서 수직
2. **가로·세로 간격이 같다** → 두 방향의 길이가 같음

화면 가운데를 원점으로 옮긴 H 의 첫째·둘째 열을 a, b 라 하면

```
직각 조건:       f² = −(a₁b₁ + a₂b₂) / (a₃b₃)
같은 간격 조건:   f² = −(a₁² + a₂² − b₁² − b₂²) / (a₃² − b₃²)
```

둘 다 구해 평균을 낸다. **프레임마다 구하고 중앙값**을 쓴다. 값이 프레임마다 얼마나 일정한지가 곧 검산이다.

| 실측 (카톡 영상 1280×720, 94프레임) | 값 |
|---|---|
| 초점거리 | **1,174 px** |
| 25~75% 범위 | 1,156 ~ 1,199 px (**±2%**) |
| 수평 시야각 | 57.2° |

렌즈 값을 아는 카메라(oCamS 등)는 보정값을 그대로 써도 된다. 해상도가 다르면 가로·세로 비율대로 늘린다.

### 3-3. 위치와 방향 (`camera_pose`)

판 좌표(m)를 칸 번호로 바꾸는 행렬 S 를 끼워, 판 좌표 → 화면의 호모그래피를 만든다.

```
        [1/0.02    0    i₀]
S   =   [  0    1/0.02  j₀]          (i₀, j₀) = 판 첫 목심의 칸 번호
        [  0       0     1]

A = K⁻¹ · H · S = λ · [ r₁  r₂  t ]
```

- r₁, r₂ = 판의 x, y 축이 카메라에서 보이는 방향 (회전 행렬의 첫째·둘째 열)
- t = 판 원점이 카메라 기준 어디 있는지
- λ = 크기. r₁, r₂ 는 길이 1 이어야 하므로 `λ = 2 / (|A₁| + |A₂|)`

그다음:

1. 판이 카메라 **앞**에 있어야 하므로 t 의 z 가 음수면 부호를 뒤집는다
2. r₃ = r₁ × r₂ 로 회전 행렬 R = [r₁ r₂ r₃] 를 만들고, 잡음으로 생긴 찌그러짐은 SVD 로 가장 가까운 회전 행렬로 바로잡는다
3. **카메라 위치 C = −Rᵀ t** (판 좌표, m)
4. 카메라가 판 아래에 나오면 z 축을 뒤집어 판 위로 맞춘다

### 3-4. 사람이 읽는 값

판 가운데에서 카메라로 가는 방향을 두 각도로 나타낸다.

| 값 | 뜻 |
|---|---|
| θ (내려다보는 각) | 판 면에서 위로 몇 도 기울어 있나 |
| φ (방위각) | 판 x 축에서 몇 도 돌아가 있나 |
| 거리 | 판 가운데에서 카메라까지 |
| 높이 | 카메라의 z |

### 3-5. 검산

| 방법 | 실측 |
|---|---|
| 직각 오차 \|r₁·r₂\| (0 이면 완벽) | **0 ~ 0.011** |
| 구한 자세로 판 900개를 다시 투영했을 때 화면 격자와의 차이 | 중앙값 **2.7 px** (1280×720, 구멍 간격 30~60 px) |
| 프레임 간 카메라 이동 | 중앙값 7 mm (부드러움) |
| 영상 속 움직임과 비교 | 높이 350 → 580 mm, θ 32° → 60° — 처음엔 비스듬히, 끝엔 위에서 내려다봄. 영상과 같다 |

사진 한 장(oCamS 보정값 사용) 에서는 **거리 0.44 m, 기울기 24.4°, 방위 165.1°** 가 나왔다.
