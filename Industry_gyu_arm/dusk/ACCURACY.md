## 왜 어려웠나 — FPU 가 없다는 것의 의미

68000 에는 소수점 연산 장치가 없다. float 을 소프트웨어로 흉내내면
한 문장에 77분이 걸린다(정수는 8.2분). 그래서 정수로 다시 짜야 하는데,
**FPU 가 자동으로 해주던 "이 값이 지금 몇 배인가"를 손으로 관리**해야 한다.
오늘 잡은 버그는 전부 그 관리에서 나왔다.

---

## 잡은 버그 — 전부 실측 근거가 있다

### 1. int32 누산 넘침 ← 가장 컸다

```
q·k 내적 : 40개 × 32767²      = 429억  > int32(21억)
행렬곱   : 1280개 × 127 × 32767 = 53억  > int32
```

실제로 `-933,560,989` (부호가 뒤집힌 값) 이 나왔고, 어텐션 점수가
`+1.32` 여야 할 자리에 `-0.37` 이 나왔다.

**해결**: 어텐션은 폭을 줄이고(±5000), 행렬곱은 int64 로 누산한다.
68000 에서 int64 누산은 `ADD.L` + `ADDX.L` 두 명령이라 부담이 없다.

### 2. LayerNorm gamma 를 128 로 더 나눈 것

```c
/* 틀림 */ nv = (nv * g[i] * scale_q) >> (7+16);
/* 맞음 */ nv = (nv * g[i] * scale_q) >> 16;
```

int8 을 실수로 되돌리는 몫(1/128)이 `scale` 안에 이미 들어 있는데
`>>7` 을 또 했다. gamma 1.0 이 0.0078 이 되어 **LayerNorm 출력이
정답의 1/118** 이었다 (rms 0.0077 vs 0.91).

### 3. KV 캐시에 그 시점의 스케일을 저장 안 한 것 ← 마지막 관문

과거 위치의 k·v 를 **현재 토큰의 스케일**로 되돌리고 있었다.
층마다 스케일이 다르므로 먼 과거일수록 틀어진다.

증상이 정확했다 — 틀린 답이 **긴 답에 몰렸고**, 갈리는 위치가
37~93 번째 글자에 집중됐다.

**해결**: 위치마다 `kmant/kshift`, `vmant/vshift` 를 함께 저장한다.
→ **91% → 100%**

### 4. 스케일 가수 정규화 누락

`mul_scale` 을 세 번 곱하니 shift 가 61까지 누적되어 배율이 40만 배
틀어졌다. 잔차에서 한쪽 항이 통째로 묻혔다.
→ 가수를 [16384, 65536) 로 정규화.

### 5. 활성값 범위 ±1.0 이 부족

LayerNorm 출력은 ±3σ 까지 간다(실측 1.68). Q15 는 ±1.0 뿐이라
포화됐다. GELU 표도 ±4.0 범위로 다시 구웠다 (MLP 중간값 ±2.79).

---

## 설계 원칙 — 실패에서 배운 것

**스케일을 층 사이로 들고 다니지 않는다.**

처음에는 지수(exp)를 층 사이로 넘기는 "블록 부동소수점" 방식을 썼다.
오차가 쌓여 20% 에서 멈췄다.

검증된 방식은 단순하다:

```
각 연산마다  ① 입력 최대값으로 스케일을 만든다
             ② int16 으로 눌러 정수 곱셈
             ③ 결과를 바로 원래 크기로 되돌린다
```

스케일은 `(가수 int32, 지수 int8)` 쌍으로 다룬다 — 곱셈 한 번과
시프트 한 번이면 되므로 68000 에서도 싸다.

---

## 검증 방법 — 이게 핵심이었다

**정답(C++ float)에서 출발해 한 단계씩 정수로 바꿨다.**

| 단계 | 정확도 |
|---|---|
| float 원본 | 100% |
| + 행렬곱 정수 | 100% |
| + LayerNorm 정수 | **0%** ← 여기서 범인 확정 |
| + GELU 정수 | 100% (LN 고친 뒤) |
| + 어텐션 정수 | 100% |

한 번에 다 정수로 바꿨으면 어디가 문제인지 못 찾았다.
그 결과가 `REFERENCE_int.cpp` (C++, 200/200) 이고,
그걸 `dusk_rachel.c` (C, 68000용) 로 옮겼다.

**층별 활성값을 정답과 직접 대조**하는 것도 결정적이었다.
코사인 유사도로 보면 어느 층에서 갈리는지 바로 보인다.

## 진단 도구

```bash
./diag.sh                    # 정답과 층별 대조
python3 verify_dusk.py 200   # 200개 완전 일치 검증
./build.sh test              # 커널 단위 검증

DUSK_VEC=1   ./dusk ...      # 층별 활성값
DUSK_V2=1    ./dusk ...      # 층별 x (새 설계)
DUSK_RES2=1  ./dusk ...      # 잔차 두 항의 실제 크기
DUSK_QKV=1   ./dusk ...      # LayerNorm·q·v 크기
```

`vs.py` (상주 모드) 를 쓰면 C++ 쪽 200개 검증이 75초에 끝난다 —
매번 프로세스를 새로 띄우면 가중치 9.6MB 로딩이 문장마다 붙는다.
