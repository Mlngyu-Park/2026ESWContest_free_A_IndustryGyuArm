# RACHEL

Robot Arm Command Handling Embedded Language-model.
ARM STUDIO 전용으로 **밑바닥부터 직접 만든** 소형 언어 모델.
사람의 한국어 명령을 로봇 블록 JSON으로 번역하는 일 하나만 한다.

```
장면: d8=빨강 d9=주황 d12=노랑 | ppap=초록@d8
명령: 레이첼아 빨간 도킹의 초록 펜을 노란 데로 옮겨
답:   {"blocks": ["@goto:d8", "@grasp:ppap", "@goto:d12", "@release:d12"]}
```

범용 LLM(Gemma 파인튜닝)과 별개로, 엣지 장비(LattePanda급) CPU에서
1초 안에 답하는 것이 목표다. 아키텍처·토크나이저·데이터·학습 전 과정을
이 폴더 안의 코드로 재현할 수 있다.

## 만든 과정

### 1단계 — 데이터 생성 (`gen_data.py`)

규칙 기반으로 10만 쌍을 합성한다. 설계 원칙:

- **장면 인식**: 색↔도킹 배치는 매번 다르다. 색을 무작위로 배정한 장면
  헤더를 입력에 넣어, 모델이 외우지 않고 **장면을 읽고** 답하게 한다.
- **색 지칭이 주력(70%)**: "빨간 도킹", "노란 데", "초록색 펜" — 색으로
  부르는 명령을 절대적으로 잘하는 것이 목표라 비중을 크게 뒀다.
- **2단계 이송 포함**: "A의 펜을 B에 놓고 다시 C로" — 실제 시연 명령.
- **STT 오염 재현**: 실사용 로그에서 본 오인식("도킹"→"토킹"), 띄어쓰기
  붕괴, 어미 변형을 확률적으로 섞는다.
- **거절 학습**: 장면에 없는 색·번호, 할 수 없는 요청("커피 타줘")은
  빈 블록으로 — 환각 방지.
- 호출명 "레이첼"이 붙어도 무시하고 명령만 처리하게 학습.

### 2단계 — 결정론 전처리 (`hints.py`)

색→도킹 조회는 사전 찾기라서 계산으로 완벽하게 된다. 신경망에 외우게
시키지 않는다 — 실측으로 확인한 결정이다. 조회를 모델에 맡긴 판은
색 지칭 정확도가 62~65%에서 멈췄고, 20줄짜리 전처리로 빼자 99.6%가 됐다.

전처리는 문장에서 색·번호 언급을 찾아 언급 순서대로 도킹 id 를 나열해
입력에 붙인다. 모델에 남는 일은 "어느 것이 출발·경유·도착인가" 라는
언어 구조 판단뿐이다.

```
힌트 d4 d14 d5
도킹 4번의 펜대 파란 도킹에 놓고 다시 보라색 스테이션에 꽂아줘
```

### 3단계 — 토크나이저 (`tokenizer.py`)

글자 단위. 명령 어휘가 좁아(색 6개·동작 7개) 서브워드가 필요 없다.
학습 데이터에서 어휘를 수집해 vocab.json 으로 저장 — 약 1천 자.

### 4단계 — 모델 (`model.py`)

GPT 구조 decoder-only 트랜스포머, 약 1천만 파라미터:

| 항목 | 값 |
|---|---|
| 차원 | 320 |
| 층수 | 8 |
| 어텐션 헤드 | 8 |
| 문맥 길이 | 256자 |
| 출력 임베딩 | 입력과 공유 |

### 5단계 — 학습 (`train.py`)

- 시퀀스: `장면\n명령\n>답<eos>` — 손실은 **답 부분에만** 건다
  (장면·명령을 외우는 데 용량을 쓰지 않게)
- AdamW + 코사인 감쇠, bf16, 6 에폭
- 에폭마다 검증 손실 + **완전 일치율**(생성 JSON == 정답) 측정, 최고만 저장
- DGX Spark GPU에서 학습

### 6단계 — 평가 (`infer.py`)

- `--bench`: 검증셋 완전 일치율 + 평균 지연
- greedy 디코딩(temperature 0) — 같은 입력은 항상 같은 출력

## 재현

```bash
python gen_data.py 100000   # train.jsonl / val.jsonl
python train.py             # rachel.pt (GPU 권장)
python infer.py --bench
python infer.py "d8=빨강 d9=노랑 | ppap=초록@d8" "빨간 데 펜 노란 도킹에 꽂아"
```

## 왜 작게 만들었나

- 로봇 명령 번역은 좁은 문제다 — 범용 지식이 필요 없다
- 1천만 파라미터 ≈ 20MB → 엣지 CPU에서 밀리초~초 단위 응답, GPU·클라우드 불필요
- 결정론(greedy) + 서버 측 출력 검증 계층 → 같은 명령은 항상 같은 블록
- 못 알아들으면 빈 블록 → 서버가 되묻는다. 규칙 파서 폴백도 유지

## 결과

검증 3,000문항 기준 (학습에 안 쓴 문제):

| 항목 | 정확도 |
|---|---|
| 전체 완전 일치 | **100 / 100** |
| 색 지칭 | 99.6% |
| 2단계 이송 | 100% |
| 거절(모르는 요청) | 100% |

지연: GPU 83ms · CPU 1.2초. 모델 파일 38MB.

시행착오 기록 — 같은 데이터·같은 크기에서 접근만 바꾼 결과:

| 판 | 접근 | 색 지칭 |
|---|---|---|
| v1 | 장면표를 주고 모델이 조회 | 62.7% |
| v2 | 장면표 방향을 색=도킹으로 | 65.2% |
| v3 | 조회 결과를 먼저 쓰게(답안지) | 64.0% |
| v4 | **조회를 결정론 전처리로 이관** | **99.6%** |

1천만 파라미터 모델에게 표 조회는 무리였고, 언어 구조 판단은 쉬웠다.
신경망과 계산의 경계를 어디에 긋느냐가 정확도를 결정했다.
