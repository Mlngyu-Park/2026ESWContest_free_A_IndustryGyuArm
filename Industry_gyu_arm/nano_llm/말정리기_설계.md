# 말 정리기 (가칭) — 설계

**2026-10-29 · 지저분한 말을 정해진 깔끔한 문장으로 바꾸는 전처리 AI**

---

## 1. 왜 만드나 — 실측 근거

실제로 한 말 87개(이송 명령)를 RACHEL v9 에 넣었다 (앱과 같은 힌트·C 추론기).

| 입력 | RACHEL v9 (재학습 없음) |
|---|---|
| 한 말 그대로 | 49/87 (56%) |
| **사람이 정해진 꼴로 다시 쓴 문장** — "보라색 도킹의 초록 펜을 빨간색으로 옮긴 다음 주황색으로 옮겨" | **86/87 (99%)** |
| 정해진 꼴 — "…빨간색으로 옮겼다가 주황색으로 옮겨" | 86/87 (99%) |
| 정해진 꼴 — "…빨간색, 주황색 순서로 옮겨" | 61/87 (70%) |

**말만 깔끔해지면 지금 RACHEL 로도 56% → 99% 가 된다.** RACHEL 이 못 하는 것은 "블록 만들기"가 아니라 "처음 보는 말투 읽기"다. 그 일을 따로 맡는 모델을 둔다.

출력 꼴을 고르는 것도 중요하다. "순서로" 꼴은 70% 에 그쳤다. **"~로 옮긴 다음 ~로 옮겨" 를 정해진 꼴로 쓴다.**

## 2. 자리 — 파이프라인

```
음성 인식 → [말 정리기] → 안전 검사(계산) → 힌트(계산) → RACHEL → 블록 검증(계산)
              말 → 깔끔한 말     │ 실패하면 원문 그대로
```

- **AI 경계선 그대로:** 정리기는 **말을 말로만** 바꾼다. 장면(어느 색이 몇 번 도킹인지)도 모르고, 좌표·블록도 만들지 않는다.
- **장면을 몰라도 된다:** 색은 낱말이고, 출발지를 말 안 했으면 정리기도 빼 둔다. 펜이 어디 있는지는 RACHEL 이 장면에서 읽는다. 그래서 장면이 바뀌어도 정리기는 그대로 쓴다.
- **FIXER 와의 관계:** FIXER 는 글자 오류(겹침·오인·반복)만 고치고 말투는 그대로 둔다. 정리기는 말투까지 정해진 꼴로 바꾼다. 처음엔 FIXER → 정리기로 잇고, 정리기 데이터에 FIXER 의 오염 다섯 가지를 넣어 성능이 같거나 나으면 **정리기 하나로 합친다.**

## 3. 입력·출력 규격 — "정해진 꼴" 문법

출력은 아래 꼴만 쓴다. 이 밖의 문장은 내지 않는다.

| 뜻 | 출력 꼴 | 예 |
|---|---|---|
| 이송 1번 | `[출발] 펜을 [도착]으로 옮겨` | 보라색 도킹의 초록 펜을 빨간색으로 옮겨 |
| 이송 여러 번 | `[출발] 펜을 [A]으로 옮긴 다음 [B]으로 옮긴 다음 … [끝]으로 옮겨` | 보라색 도킹의 초록 펜을 빨간색으로 옮긴 다음 주황색으로 옮겨 |
| 출발을 말 안 함 | `초록 펜을 …` (출발 없이) | 초록 펜을 빨간색으로 옮겨 |
| 잡기만 / 놓기만 | `[출발] 펜을 잡아` / `[도착]에 놓아` | 보라색 도킹의 펜을 잡아 |
| 제자리 | `그리퍼 열어` · `그리퍼 닫아` · `내려` · `올려` | |
| 앱 조작 | `정지` · `초기화` · `미리보기` · `빠르게` · `천천히` | "비우고 …" → `초기화` + 뒤 명령 |
| 명령 아님 | `(명령 아님)` | 인사·잡담·끊긴 말 |
| (두 팔, 정해지면) | 줄마다 `1번 팔: …` / `10초 기다려` / `2번 팔: …` | |

규칙:
- **정정은 마지막 말만 남긴다:** "빨간색 아니 주황색으로" → `주황색으로`, "빨간색으로 옮기지 말고 주황색으로" → `주황색으로 옮겨`
- **"다시 그 펜을 잡아서", "빨간색에 있는 초록색 펜을 잡아서"** (방금 놓은 자리를 다시 부르는 말) → 단계를 늘리지 않는다
- **색은 표준 낱말로:** 빨간·붉은·레드 → 빨간색, 오렌지 → 주황색, 키록색 → 초록색. 번호는 그대로 (`3번 도킹`)
- **펜 별칭 통일:** 피피에이피·PPAP·팬·핀·캔·그거 → 펜
- **모르는 색은 그대로 둔다** (예: 노란색). 지어내지도 빼지도 않는다 — 장면에 없으면 힌트 계산이 거절한다

## 4. 안전 검사 — 계산이 정리기를 검사한다

AI 출력은 그대로 믿지 않는다 (FIXER 와 같은 원칙). 아래 중 하나라도 걸리면 **원문을 그대로** 다음 단계로 넘기고, 둘 다 기록한다.

| 검사 | 내용 |
|---|---|
| 색·번호를 지어내지 않았나 | 출력의 색·번호 목록이 원문 언급 순서의 **부분 수열**이어야 한다 (정정·반복으로 빠지는 건 괜찮고, 새로 생기거나 순서가 바뀌면 안 된다) |
| 꼴을 지켰나 | 출력이 3절 문법 중 하나와 정규식으로 맞아야 한다 |
| 명령을 지우지 않았나 | 원문에 색·동사(옮기·이동·놓·꽂·잡)가 있는데 `(명령 아님)` 이면 의심 → 원문 사용 |
| 길이 | 출력이 원문보다 길면 이상 → 원문 사용 |

## 5. 모델

RACHEL·FIXER 와 **같은 구조**(글자 단위 GPT, 디코더만)를 쓴다. 그래서 C++ 추론기(`rachel_cpp`)와 정수 엔진(DUSK)을 가중치만 바꿔 그대로 쓴다.

| 안 | 차원·층 | 파라미터 | int8 크기 | 문맥 |
|---|---|---|---|---|
| 작게 | d320 L8 | 약 10M | 10 MB | 512 |
| **기본** | **d384 L10** | **약 18M** | **18 MB** | **512** |
| 크게 | d448 L10 | 약 24M | 24 MB | 512 |

- 입력은 최대 약 300자(잡담 포함 실제 말), 출력은 짧다(대부분 60자 안). 문맥 512면 충분하다.
- 크기는 키워도 된다(사용자 확인). 기본안 18M 으로 시작하고, 시험(7절)에서 모자라면 키운다.
- **지연은 아직 추정**이다. v9(10M) 은 노트북에서 중앙 180 ms 였다. 정리기는 출력이 짧아 비슷하거나 짧을 것으로 보지만, 라떼판다에서 직접 재야 한다.

## 6. 학습 데이터 — 「말투 엔진」 (가장 중요)

말투가 이 일의 전부다. **뜻 하나에서 깔끔한 정답과 지저분한 입력을 같이 만든다.** 정답이 생성 순간 정해지므로 라벨이 틀릴 일이 없다. 같은 엔진을 RACHEL v10 데이터에도 쓴다.

```
뜻 (경로·정정·조작·명령 아님)
  ├─▶ 정해진 꼴로 쓰기  → 정답 (dst)
  └─▶ 말투 엔진         → 입력 (src)
        ① 문장 뼈대    동사 × 활용 × 연결어
        ② 감싸기       앞말 · 맺음말 · 잡담
        ③ 끼어들기     정정 · 머뭇거림 · 반복 · 다시 잡기
        ④ 음성 오염    실제 기록에서 가져온 오류
```

### 6-1. 문장 뼈대 — 조합으로 만든다 (틀을 늘리지 않는다)

| 요소 | 목록 |
|---|---|
| 동사 | 옮기다 · 이동하다 · 이동시키다 · 갖다 놓다 · 갖다 두다 · 놓다 · 두다 · 꽂다 · 넣다 · 보내다 · 가져가다 |
| 활용 | 옮긴 · 옮기고 · 옮겼다가 · 옮겨서 · 옮겨 놓고 · 옮겨 둔 · 옮기면 |
| 연결어 | ~한 다음(에) · ~한 후(에) · ~한 뒤(에) · ~하고 나서 · ~하고 · ~하고 다시 · ~했다가 · ~해서 · 그리고 나서 · 그 다음(에) · 이어서 · ~하면 · 마지막으로 · 최종적으로 · 끝으로 · 한 번 더 |
| 장소 부르기 | 빨간색 · 빨간 도킹 · 빨간색 도킹 스테이션 · 빨간 데 · 빨간 자리 · 3번 도킹 · 3번 |
| 펜 부르기 | 펜 · 초록색 펜 · 초록 펜대 · 그거 · 그 펜 · 피피에이피 · 물체 |
| 다시 잡기 | 다시 그 펜을 잡아서 · 빨간색에 있는 초록색 펜을 잡아서 · 그걸 다시 |

연결어마다 **최소 수만 번** 나오게 고르게 섞는다 (v9 는 "후·뒤·나서"가 0번이었다).

### 6-2. 감싸기 — 실제 말 길이(60~220자)로

- 앞: 내가 하고 싶은 건 · 내가 원하는 건 · 하고 싶은 공정은 · 해보고 싶은 건 · 자 · 야 · 레이첼
- 뒤: ~는 거 하고 싶어 · ~했으면 좋겠어 · ~해보고 싶어 · ~하는 거야 · ~해줘 봐 · 알겠지 · 어렵게 말했는데 알아서 해봐
- 잡담: 앞뒤에 명령과 상관없는 말 (실제 기록처럼 옆 사람 대화, 인사, 혼잣말)

### 6-3. 끼어들기

- 정정: "아니", "아 정정", "말고", "~하지 말고", "아니 아니"
- 머뭇거림: "음…", "그…", "어~", 말 끊김("빨간….색으로")
- 반복: 같은 말 2~3번, "내가 하고 싶은 건 내가 하고 싶은 건"
- 1단계 함정: "잡은 다음에 / 잡은 후에 / 잡고 나서 빨간색으로 옮겨" = 이송 1번

### 6-4. 음성 오염 — 실제 기록(`llm_usage.jsonl`)에서 본 것

| 오염 | 실제 예 |
|---|---|
| 도킹 오인 | 토킹 · 쿠킹 · 카페 스테이션 |
| 펜 오인 | 팬 · 핀 · 캔 · 맥켄 · 팬싸인 |
| 색 오인 | 키록색 · 주화앙 · 두 방색 |
| 반복 루프 | 색 색 색 … · 처음 봤습니다 ×3 |
| 띄어쓰기 | 붕괴 · 엉뚱한 자리 |
| 겹침 중복 | (FIXER 의 다섯 가지 그대로) |

### 6-5. 양과 비율

| 종류 | 비율 |
|---|---|
| 이송 1번 | 28% |
| 이송 2번 | 22% |
| 이송 3~5번 | 18% |
| 1단계 함정 | 5% |
| 정정 | 7% |
| 잡기·놓기·제자리·앱 조작 | 5% |
| **명령 아님** | **15%** |

- 총 **약 150만 쌍** (RACHEL v10 의 8배 계획과 같은 규모)
- 길이: 60자 이하 30% · 60~150자 45% · 150~300자 25%
- **떼어 두기:** 연결어 3개·감싸기 3개를 학습에서 일부러 빼고, 시험에만 쓴다 (처음 보는 말투에 얼마나 버티는지)

### 6-6. (선택) 큰 모델로 말투 늘리기

Spark 의 큰 모델(Gemma·Qwen)에게 지저분한 입력을 **바꿔 말하게** 해서 말투를 더 다양하게 할 수 있다 (FIXER 도 `gemma_data.jsonl` 1,526개를 썼다). 이건 **데이터를 만들 때만** 쓰고 앱에는 들어가지 않는다. 바꿔 말한 문장도 4절 안전 검사(색 순서)를 통과한 것만 쓴다.

## 7. 시험 — 합성 검증셋만 믿지 않는다

| 시험 | 재는 것 | 목표 |
|---|---|---|
| 실제 말 98문장 | 정리기 출력 → RACHEL v9 블록이 정답과 같은가 | **95% 이상** |
| 연결어 시험 | 연결어 18 → 30가지 × 말투 × 단계 수 (300문장) | **98% 이상** |
| 떼어 둔 말투 | 학습에 없던 연결어·감싸기 | 기록 (일반화 정도) |
| 안전 검사 걸림 비율 | 원문으로 되돌린 비율 | 5% 이하 |
| 색 지어냄 | 원문에 없는 색이 출력에 나온 횟수 | **0** |
| 지연 | 노트북·라떼판다 | 재서 기록 |

실제 말 98문장의 정답은 사람이 확정해야 한다 (`paper_evidence/07_HUMAN_SENTENCES.md`).

## 8. RACHEL 은 어떻게 되나

- 정리기가 있으면 RACHEL 이 받는 말은 **늘 정해진 꼴**이다 → 지금 v9 로도 99%.
- 그래도 정리기가 안전 검사에 걸려 **원문이 그대로 오는 경우**가 있다. 그때를 위해 RACHEL v10 도 같은 말투 엔진으로 학습해 둔다 (`RACHEL_한계와_v10계획.md`).
- RACHEL 도 크기를 키워도 된다 (d384~448, 18~24M, 문맥 512). 정리기와 같은 엔진이라 추론기는 하나로 쓴다.

## 9. 순서

1. **말투 엔진** 만들기 (`nano_llm/gen_data.py` 를 뜻 → 정답/입력 구조로 다시 짠다. `import os` 빠진 것도 고침)
2. 정해진 꼴 문법 + 안전 검사(계산) 코드 — 학습 전에 실제 말 98개를 **사람이 정해진 꼴로 쓴 것**으로 검사가 통과하는지 확인
3. 데이터 150만 쌍 생성 → 연결어·길이·종류 분포 확인
4. 정리기 학습 (DGX Spark, 기본안 18M)
5. 7절 시험 → 통과하면 앱에 넣기 (실패 시 원문 그대로라 앱이 나빠지지는 않는다)
6. 같은 말투 엔진으로 RACHEL v10 학습
7. `llm_usage.jsonl` 에 **장면 줄·정리기 출력도 같이 기록** → 다음 학습의 실제 데이터

## 10. 남는 위험

- 실제 말은 아직 화자 1명(저자)뿐이다.
- 말투 엔진에 없는 말투는 정리기도 처음 본다 → 떼어 둔 말투 시험으로 그 크기를 재고, 실사용 기록을 계속 모아 메운다.
- 모델이 둘이 되면 지연이 더해진다 → 라떼판다에서 재고, 필요하면 정리기를 작게 한다.
