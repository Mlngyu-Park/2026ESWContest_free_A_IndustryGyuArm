## 1. 한 줄 요약

**합성 검증 98.5% 는 "학습 문장 틀 안에서" 의 점수다. 실제로 한 말은 56%, 연결어만 바꾼 시험은 46% 다.** 원인은 모델 크기가 아니라 학습 데이터다 — 실제 말투(긴 문장, "옮긴 후/나서", "하고 싶은 건 …싶어")를 한 번도 본 적이 없다.

## 2. 측정 결과

### 2-1. 실제로 한 말 (`llm_usage.jsonl` 106문장 → 뜻이 갈리는 8문장 빼고 98문장)

장면은 "말에 나온 색의 도킹은 다 있다" 로 놓고, 경로를 맞게 읽었는지만 봤다.

| 항목 | 결과 |
|---|---|
| 이송 명령 | **49/87 (56%)** |
| 명령이 아닌 말 (인사·잡담·끊긴 말) | 5/11 — 나머지 6개는 블록을 만들었다 (`@down`, `@up`, 이송) |
| 장면에 없는 색 → 거절 | **0/26** (도킹 3개 장면에서 따로 잼) |

| 문장 길이 | 이송 명령 정확도 |
|---|---|
| 40자 이하 | 19/22 (86%) |
| 60자 이하 | 30/35 (86%) |
| 80자 초과 | 6/32 (19%) |
| **100자 초과** | **0/14** |

틀린 38개의 모양: **같은 이송을 되풀이해 단계를 더 만듦 31개** (예: 정답 보라→빨강, 모델 보라→빨강→빨강→빨강), 단계 빠뜨림 5개. 긴 문장에서는 장면에 없는 도킹 번호(d1·d7·d8)를 지어냈다 — 입력이 문맥 179자를 넘어 장면 줄이 밀려난 것이다.

### 2-2. 연결어 시험 (`paper_evidence/16_CONNECTIVE_PROBE_1029.json`)

같은 내용(보라 도킹의 초록 펜 → 빨강 → 주황)을 **연결어 18가지 × 말투 4가지 = 72문장**으로 바꿔 넣었다.

- "잡은 후에 빨간색으로 옮겨줘" (1단계)도 틀렸다 (보라에서 멈춤). "잡은 다음에" 는 맞힌다.
- 틀리는 모양은 둘뿐이다: **가운데 단계를 빠뜨리거나, 마지막 단계를 한 번 더 붙인다.**

## 4. v10 계획

### 4-1. 데이터 — 8배 (약 15만 → 약 120만 문장)

늘리는 양보다 **무엇을 늘리느냐**가 중요하다. 지금 틀을 8배로 찍어내면 같은 말투만 8배가 된다.

**① 연결어를 문법으로 만든다 (틀을 늘리는 대신 조합)**

동사 × 활용형 × 연결어를 조합한다. 학습에 한 번이라도 나오게 하고, 각각 고르게 섞는다.

| 동사 | 옮기다 · 이동하다 · 이동시키다 · 갖다 놓다 · 놓다 · 두다 · 꽂다 · 넣다 · 보내다 |
|---|---|
| 연결 | ~한 다음(에) · ~한 후(에) · ~한 뒤(에) · ~하고 나서 · ~하고 · ~하고 다시 · ~했다가 · ~해서 · 그리고 나서 · 그 다음(에) · 이어서 · ~하면 · 마지막으로 · 최종적으로 · 끝으로 |
| 다시 잡기 | 다시 그 펜(을) 잡아서 · 빨간색에 있는 초록색 펜을 잡아서 (← 지금 펜이 있는 자리를 다시 부르는 말. **단계를 늘리지 않는다**) |

**② 실제 말투로 감싼다 (길이 60~220자)**

- 앞: "내가 하고 싶은 건 / 원하는 건 / 하고 싶은 공정은 / 해보고 싶은 건", 이름 부르기, 머뭇거림
- 뒤: "~는 거 하고 싶어 / 좋겠어 / 해보고 싶어 / 하는 거야 / 해줘 봐", "알겠지", "어렵게 말했는데 알아서 해봐"
- 중간: 말 고치기("아니 정정하자"), 같은 말 반복, 머뭇거림("음…")
- 앞뒤 잡담 섞기 (실제 기록처럼 옆 사람 말이 붙은 것)

**③ 음성 오염을 실제 기록에서 가져온다**

토킹·쿠킹 스테이션, 피피에이피·PPAP·팬·핀·캔, 키록색·주화앙, "색 색 색" 반복, 띄어쓰기 붕괴.

**④ 거절·명령 아님을 늘린다 (7% → 약 15%)**

인사, 끊긴 말("내가 원하는 건"), 자기 질문("너 누구야"), 잡담 → 빈 답. 장면에 없는 색은 4-3 처럼 계산이 거절한다.

**⑤ 헷갈리는 1단계를 일부러 넣는다**

"잡은 다음에/잡은 후에/잡고 나서 빨간색으로 옮겨" = 1단계. "옮기지 말고 / 말고" 정정.

**⑥ (정해지면) 두 팔 어휘**

"1번 팔이 …, 10초 뒤에 2번 팔이 …" → 팔·대기 블록. 데이터를 두 번 만들지 않도록 이번에 같이 넣는 것이 좋다.

**섞는 비율 (안)**

| 종류 | 비율 |
|---|---|
| 1단계 이송 | 30% |
| 2단계 | 22% |
| 3~5단계 | 18% |
| 1단계지만 연결어가 있는 것 (잡은 후에 등) | 5% |
| 정정·부정 | 5% |
| 제자리·조작·속도 | 5% |
| 거절·명령 아님 | 15% |

길이: 60자 이하 40% · 60~120자 40% · 120~220자 20%.

### 4-2. 모델·추론기

| 항목 | v9 | v10 |
|---|---|---|
| 문맥 | 179 | **512** (장면+힌트 약 60 + 문장 최대 220 + 답 최대 250) |
| 크기 | 10.1M | 거의 같음 (위치 표만 늘어남) |
| 생성 한도 (`rachel.cpp`) | 200 | **400** |

### 4-3. 계산으로 옮길 것 (`hints.py` — 학습과 앱이 같은 함수를 쓴다)

- **장면에 없는 색·번호를 말하면 계산이 거절한다** (지금 0/26). 색 조회를 계산으로 옮겨 65% → 99.6% 가 된 것과 같은 원리다.
- "초록 펜"은 **처음 나올 때만** 출발지로 짚는다 (지금은 두 번째 "초록색 펜"도 처음 자리로 짚어 힌트가 틀린다).
- 펜이라는 말 없이 펜 색만 말해도 펜으로 본다 ("초록색 잡아서").
- 펜 별칭·오타 표를 늘린다.
- 두 팔: "N번 팔"·"N초 뒤" 를 계산이 뽑는다 (지금은 "1번"을 1번 도킹으로 읽는다).

※ 힌트 규칙을 바꾸면 **반드시 다시 학습**해야 한다. 학습 없이 힌트만 바꿨더니 효과가 0 이었다 (49/87 그대로).

### 4-4. 평가 — 합성 검증셋에 의존하지 않는다

| 시험 | 내용 | 목표 |
|---|---|---|
| 실제 말 98문장 | 정답은 사람이 확정 (`paper_evidence/07_HUMAN_SENTENCES.md`) | **85% 이상** |
| 연결어 시험 | 72 → 300문장으로 늘림 (연결어·말투·단계 수 조합) | **95% 이상** |
| **떼어 둔 말투 시험** | 연결어 몇 개를 학습에서 일부러 빼고 시험 → 처음 보는 말투에 얼마나 버티는지 | 기록 |
| 합성 검증 | 기존과 비교용 | 97% 이상 유지 |

### 4-5. 순서

1. `gen_data.py` 고치기 (`import os`) + 연결어 문법·말투·잡음·거절 추가
2. `hints.py` 거절·펜 언급 규칙 (학습과 앱 동시)
3. 데이터 120만 생성 → 길이·연결어·단계 분포 확인
4. 학습 (DGX Spark, 문맥 512). v9 은 15만×8에폭에 약 33분이었다. 120만에 문장이 길어져 **수 시간**으로 본다 — 에폭 수를 줄여 조절
5. 4-4 시험 전부 → v9 과 나란히 비교
6. 통과하면 `rachel.bin` 교체 (v9 은 `rachel_v9.bin` 으로 보관), `rachel.cpp` 생성 한도 400

### 4-6. 그래도 남는 것

- 실제 말은 화자 1명(저자) 기록뿐이다. 다른 사람 말투에 대한 근거가 없다.
- 학습은 여전히 규칙으로 만든 문장이다. 생성기에 없는 말투는 또 못 할 수 있다 → "떼어 둔 말투 시험"으로 그 정도를 잰다.
- 실제 기록에 그때 장면이 남지 않는다 → 앞으로는 `llm_usage.jsonl` 에 **장면 줄도 같이 기록**하게 고친다.
