# RACHEL 다음 판 계획 (v9)

지금 당장 학습하지 않는다. **나중에 할 때 이 문서대로 하면 된다.**

지금 판(v8)은 도킹 3개·블록 3종·3단계까지만 다룬다.
앞으로 하고 싶은 것: **도킹 더 많이 + 복잡한 블록(가로 놓기 등)**

---

## 지금 상태 (v8) — 무엇이 되고 무엇이 안 되나

| | 값 |
|---|---|
| 크기 | 9.61MB (int8) · 학습 파일 38.3MB |
| 구조 | d320 L8 H8 **ctx320** · 어휘 174자 |
| 검증 | 200/200 = 100% · 실사용 회귀 3/3 |
| 속도 | C++ 상주 183ms |

### 되는 것

- 색 지칭 ("빨간 도킹", "오렌지 색으로")
- 부정·정정 ("빨간색으로 옮기**지 말고** 주황색으로")
- **3단계까지** 이송 (A→B→C)
- STT 오염, 군말, 호명, 거절

### 안 되는 것 — 실측으로 확인함

6색 6도킹 장면을 만들어 시험한 결과다.

| 요청 | 기대 | 실제 |
|---|---|---|
| "빨간색으로 **옮겼다가** 노란색으로" | d3 → d7 | d5 → d7 ❌ |
| 3단계 "옮겼다가" 말투 | 3곳 | 2곳 ❌ |
| 4단계 "빨강, 노랑, 보라, 주황 순서로" | 4곳 | 3곳 ❌ |
| **6단계** | 6곳 | **2곳** ❌ |

**힌트(`hints.py`)는 정확했다.** 6색을 순서대로 다 잡아냈다
(`d3 d5 d7 d9 d11 d13`). 못 하는 건 모델 쪽이다.

원인 두 가지:

1. **학습 데이터에 3단계까지만 있다.** 4단계 이상은 한 번도 안 배웠다.
2. **"옮겼다가" 말투를 안 배웠다.** v7 데이터는 "옮기고 다음에",
   "갔다가", "→ 순서로" 위주였다. 이건 단계 수와 무관한 문제다.

## v9 에서 할 것

### 1. 도킹을 더 많이 (색 6개 전부)

지금 배치는 도킹 3개(빨강·주황·노랑)뿐이다. 6색을 다 쓰려면
도킹을 6개 놓아야 하고, 학습 데이터도 그 장면을 반영해야 한다.

`gen_data.py` 의 `scene()` 이 이미 색을 무작위로 배정하므로
**데이터 쪽은 바꿀 게 없다.** 실제 배치만 늘리면 된다.

다만 확인할 것:
- 도킹이 많아지면 프롬프트의 장면 부분이 길어진다
  (6색 = `빨강=d3 초록=d5 노랑=d7 보라=d9 주황=d11 파랑=d13 | 펜=초록@d5`)
- 문맥 320 으로 충분한지 재봐야 한다 (아래 4번)

### 2. 4단계 이상 이송

`gen_data.py` 에 3단계 블록이 있다 (`kind < 0.60`).
같은 방식으로 4~6단계를 넣으면 된다.

```python
# 지금 (3단계)
m1, m2, dst = random.sample(others, 3)

# v9 (n단계, n = 2~6 무작위)
n = random.randint(2, 6)
if len(others) < n: continue
stops = random.sample(others, n)
blocks = [f"@goto:{home}", "@grasp:ppap"]
for s in stops:
    blocks += [f"@goto:{s}", f"@release:{s}", "@grasp:ppap"]
blocks.pop()          # 마지막 잡기는 없다
```

### 3. "옮겼다가" 말투 ← 단계 수와 무관, 우선순위 높음

지금 데이터에 없는 표현들:

```
"빨간색으로 옮겼다가 노란색으로 옮겨줘"
"A 갔다가 B 갔다가"          ← 일부 있음
"A 했다가 B 했다가"
"A 들렀다가 B"
"A 거쳐서 B 거쳐서 C"
```

`gen_data.py` 의 문장 템플릿에 추가하면 된다.
**이것만 고쳐도 2단계 정확도가 올라간다.**

### 4. 문맥 길이

6단계 답은 이론상 ~290자다. 프롬프트(6색 장면 + 힌트 + 명령)가
120자쯤이면 합계 410자 — **지금 문맥 320 을 넘는다.**

| 단계 | 답 길이 | 프롬프트 포함 |
|---|---|---|
| 1단계 | 68자 | ~180자 |
| 3단계 | 152자 | ~270자 |
| 6단계 | ~290자 | **~410자** |

v9 는 **ctx 448** 정도가 필요하다.

> 참고: v7(ctx256) 이 194/200 이었던 이유가 이거였다.
> 3단계 답 6건이 문맥을 1~14자 넘겨서 닫는 `}` 가 잘렸다.
> ctx320 으로 올리니 200/200 이 됐다.

파일 크기 영향은 작다 — 위치 임베딩만 늘어난다:
```
ctx 320 → 448:  (448-320) × 320 = 40,960 파라미터 = +40KB
9.61MB → 9.65MB
```

### 5. 복잡한 동작 (가로로 놓기 등)

**AI 가 하는 일은 안 바뀐다.** 새 동작이 들어와도 AI 는 여전히
"블록을 순서대로 나열"할 뿐이다. 블록 종류가 몇 개 늘 뿐이다.

#### 왜 그런가

"가로로 놓기"는 새로운 종류의 일이 아니라 **기존 블록들의 조합**이다.
지금 "잡기"가 그렇듯이:

```
잡기 =  열기 → 하강 → 닫기 → 상승        (앱이 4단계로 푼다)
가로 놓기 =  이동 → 회전 → 놓기          (블록 3개의 나열)
```

그러니 필요한 건 **블록 하나 추가**뿐이다:

```
지금:  @goto:  @grasp:  @release:            3종
추가:  @rotate:<각도이름>                     → 4종
```

AI 는 "가로로 놓아줘" 를 보고 `@rotate:` 를 사이에 끼워 넣으면 된다.
각도를 실제로 얼마로 돌릴지, IK 가 풀리는지, 충돌하는지는
**전부 앱이 계산한다.**

```
말:      "빨간 도킹에 가로로 놔줘"
AI:      ["@goto:d10", "@rotate:가로", "@release:d10"]
앱:      가로 = 90도 → IK → 충돌검사 → 모터 명령
```

#### 그래서 v10 은 큰 작업이 아니다

모델 구조도, 학습 방식도, `hints.py` 도 그대로다. 바뀌는 것:

| | 바뀌나 |
|---|---|
| 모델 구조 (d320 L8 H8) | 그대로 |
| 학습 방식 (손실을 `>` 뒤에만) | 그대로 |
| `hints.py` (색→도킹) | 그대로 |
| 어휘 | `@rotate:` 글자 몇 개 추가 |
| `gen_data.py` | 새 블록 쓰는 예문 추가 |

#### 순서 — 앱이 먼저다

1. **앱에 `@rotate:` 를 구현한다.** 손으로 블록을 만들어 동작 확인
2. 되는 걸 확인한 뒤 `gen_data.py` 에 그 블록을 쓰는 예문을 넣는다
3. 학습 → 검증

**앱에서 안 되는 걸 모델에 먼저 가르치면 안 된다.**
모델이 만든 블록을 앱이 못 실행하면 그냥 오류가 난다.

#### 블록 이름은 말에 가깝게

각도를 숫자로 넣지 말 것:

```
좋음:  @rotate:가로        모델은 말만 옮긴다
나쁨:  @rotate:90.0        모델이 숫자를 지어낼 위험
```

숫자로 바꾸는 건 앱이 한다 (`가로 → 90도`). 이게 프로젝트의
경계선 원칙이다 — 계산으로 되는 건 신경망에 안 시킨다.

#### 앞으로 늘어날 만한 블록들

앱에 이미 개념이 있는 것들이다:

| 하고 싶은 것 | 새 블록 | 앱이 이미 아는 것 |
|---|---|---|
| 가로/세로로 놓기 | `@rotate:가로` | `set_robot_pose(x,y,yaw)` |
| 특정 목심에 놓기 | `@goto:C4` | `peg_xy("0,0:C4")` A1~J10 |
| 높이 바꿔 놓기 | `@height:낮게` | `peg_z(height_mm)` |
| 잠깐 멈추기 | `@wait:2초` | — |

전부 "블록 하나 추가 + 예문 추가" 로 끝난다.

## 작업 순서 (권장)

```
1. "옮겼다가" 말투 추가          ← 제일 싸고 효과 큼
2. 4~6단계 이송 추가
3. 문맥 320 → 448
4. 학습 (약 40분, Spark)
5. 검증 (200개 + 6색 6단계 시험)
   ↑ 여기까지가 v9

6. 앱에 @rotate: 구현 (손으로 블록 만들어 확인)
7. gen_data.py 에 그 블록 쓰는 예문 추가
8. 학습 → 검증
   ↑ 여기가 v10 — 모델 쪽은 어휘 몇 글자와 예문뿐이다
```

1~5 는 하루면 된다. 6~8 은 **앱 작업이 대부분**이고
모델 쪽은 거의 안 바뀐다.

## 학습 방법 (v8 때 실제로 한 것)

```bash
# 1. 데이터 만들기 (로컬, 7초)
cd nano_llm && python gen_data.py 150000

# 2. Spark 로 올리기
#    먼저 터널을 켠다 (꺼져 있으면 접속이 안 된다)
cd .. && bash spark_link.sh && cd nano_llm
#    포트는 spark_link.sh 가 띄운 ssh 명령줄에 있다
SSH_PORT=$(pgrep -af 'ssh -f -N.*spark_key' | sed -n 's/.* -p \([0-9]*\).*/\1/p' | head -1)
echo "포트 $SSH_PORT"      # 비어 있으면 터널이 안 켜진 것
scp -i ~/.ssh/spark_key -P $SSH_PORT \
    {gen_data,hints,tokenizer,model,train,analyze,test_real}.py \
    train.jsonl val.jsonl drboom@127.0.0.1:~/nano_llm/

# 3. 학습 (약 40분)
ssh -i ~/.ssh/spark_key -p $SSH_PORT drboom@127.0.0.1 \
  "cd ~/nano_llm && RACHEL_CTX=448 nohup \
   ~/miniconda3/envs/kanon_ft/bin/python -u train.py > train_v9.log 2>&1 &"

# 4. 변환·내려받기
ssh ... "cd ~/nano_llm && ~/miniconda3/envs/kanon_ft/bin/python \
         export_weights.py rachel.pt rachel_v9.bin"
scp ... drboom@127.0.0.1:~/nano_llm/rachel_v9.bin ../rachel_cpp/

# 5. 검증
cd ../rachel_cpp && python verify.py
```

**주의**
- **터널이 자주 끊긴다.** 접속이 안 되면 `bash spark_link.sh` 를 먼저 실행할 것
- 학습은 반드시 Spark 에서 (사용자 PC 금지 — GPU 는 다른 데 써야 함)
- Spark 파이썬 환경은 `~/miniconda3/envs/kanon_ft` (torch 2.13 + CUDA)
  — `rachel` 환경에는 torch 가 없다
- `RACHEL_CTX` 등 환경변수로 구조를 바꾼다 (`train.py` 참조)
