# WHISPER DUSK — 말을 받아쓰고 다듬는 부분

```
소리  →  ears(받아쓰기)  →  fixer(다듬기)  →  깨끗한 글자
         Moonshine 27MB     자작 7.5MB           ↓
                                        hints.py → RACHEL → 블록
```

> **이름에 대하여**
> 'Whisper' 는 OpenAI 모델 이름이기도 하지만, 이 **Whisper Dusk 는
> 그것과 아무 관계가 없다.** 이 프로젝트에서 붙인 이름일 뿐이다.
> 받아쓰기는 Moonshine 한국어(Useful Sensors 의 오픈 모델), 다듬기는
> 이 프로젝트에서 직접 만든 모델이다. **OpenAI Whisper 는 쓰지 않는다.**

## 왜 둘로 나뉘어 있나

받아쓰기(`ears/`)는 27MB 짜리라 정확도가 낮다. 대신 **노트북에서 혼자
돈다** — 대회장에서 네트워크가 끊겨도 말로 조작할 수 있다.
그 대가로 말이 지저분해지는데, 그걸 `fixer/` 가 다듬는다.

AI 경계선 원칙은 그대로다. 둘 다 '말을 말로' 만 다룬다 —
좌표·경로·제어에는 손대지 않는다.

## 쓰는 법

```python
import whisper_dusk as wd
clean, raw = wd.listen(wav_bytes)   # 소리 -> 깨끗한 글자 (+ 받아쓴 원문)
wd.hear(wav_bytes)                  # 받아쓰기만
wd.polish("지저분한 말")             # 다듬기만
```

앱(`arm_studio_pro.py`)이 자동으로 쓴다. Spark(DGX) 결과는 이미
깨끗해서 다듬지 않는다.

---

# fixer — 다듬는 모델 (자작 7.5MB)

## 왜 만들었나

Moonshine 27M 은 노트북에서 도는 대신 정확도가 낮다.
실제로 이런 말이 나왔다 (2026-09-15 사용자 로그):

```
Spark(정답) : ...보라색 도킹 스테이션에 있는           초록색 펜을 잡아서
              빨간색으로 이동한 다음에           주황색으로 다시 옮기는 거
27MB(오염)  : ...보라색 도킹 스테이션에 있는 [카페 스테이션에 있는] 초록색 펜을 잡아서
              빨간색으로 이동한 다음에 [주황 운동한 다음에] 주황색으로 다시 옮기는 거
```

이 오염된 말을 RACHEL 에 그대로 넣으면 블록이 망가진다 (실측):

| 입력 | 블록 |
|---|---|
| 오염 그대로 | **10개** — `@goto:d10` 이 3번 반복 |
| FIXER 교정 후 | **7개** — 정상 |

## 오염 다섯 가지 (실측)

1. **겹침 중복** — 창을 겹쳐 돌린 자리가 두 번 들어간다 (제일 흔함)
2. **낱말 오인** — 도킹→카페, 이동→운동
3. **반복 루프** — "색 색 색 색 …" (디코더가 갇힌다)
4. **잔말** — 어, 음, 그 …
5. **끝 부호** — 마침표가 붙거나 빠진다

`fixer/gen_data.py` 가 이 다섯 가지를 재현해 학습 데이터를 만든다.

## 모델

RACHEL 과 **같은 구조**를 쓴다 (`fixer/model.py` 는 `nano_llm/model.py` 복사본).
검증된 것을 다시 만들지 않는다.

```
글자 단위 GPT · d320 L6 H8 ctx320
파라미터 7.54M · fp32 30.2MB · int8 7.5MB
어휘 119자
```

## 만들기

```bash
python gen_data.py 400000 > fix_data.jsonl     # 학습 데이터
FIX_DIM=320 FIX_LAYER=6 FIX_CTX=320 \
FIX_BATCH=256 FIX_EPOCH=12 python train.py      # 학습 (DGX Spark GPU)
```

## 쓰기

```python
import fixer
fixer.fix("어 그 초록색 색 색 색 펜을 음 잡아서 빨간 도킹이로 옮겨줘.")
# -> "초록색 펜을 잡아서 빨간 도킹 스테이션으로 옮겨줘"
```

앱이 받아쓰기 결과에만 자동으로 적용한다.
Spark(DGX) 결과는 이미 깨끗해서 손대지 않는다.

**속도**: 첫 호출 2.1초(모델 적재), 이후 **25~31ms**

## 안전장치 — 고치려다 말을 잃지 않게

`fix()` 는 결과가 미심쩍으면 **원문을 그대로** 돌려준다.
7.5M 짜리 작은 모델이라 틀릴 때가 있고, **틀린 교정은 안 고치느니만 못하다.**

| 검사 | 왜 | 실측한 사고 |
|---|---|---|
| 색이 사라지면 거부 | hints.py 가 색으로 도킹을 찾는다 | — |
| 동작이 사라지면 거부 | 색은 '어디로', 동작은 '무엇을' | — |
| 색 **순서**가 바뀌면 거부 | 순서가 곧 작업 순서 | 빨강→노랑→파랑 이 빨강→파랑→노랑 으로 뒤집힘 |
| 없던 색을 지어내면 거부 | 말 안 한 도킹으로 간다 | `"주임"` → `"주황 자"` |
| 없던 동작을 지어내면 거부 | 명령 아닌 말이 명령이 된다 | `"아 그 뭐지"` → `"하강"` |
| 결과에 반복이 있으면 거부 | 모델이 갇힌 것 | `"상승"` → `"상상상상상승"` |
| 1.35 배보다 길어지면 거부 | 헛말을 지어낸 것 | — |
| ctx 에 안 들어가면 손 안 댐 | 잘린 채 고치면 뒤가 날아간다 | — |

**길이로는 막지 않는다.** 지저분한 말을 고치면 많이 짧아지는 게 정상이다 —
`"토킹 스테이선에 있는 팬이 잡아써 빨깐 자리로 옴기는 거"` →
`"펜 잡아서 빨간 자리로 옮겨줘"` 는 0.52 배지만 정답이다.
길이 대신 **뜻(색·동작·순서)이 남았는지** 로 본다.

색·동작 검사는 **종류만** 본다(개수 아님). 겹침 중복이면 같은 색이 두 번
나오는데 그 중복을 지우는 게 FIXER 가 할 일이라, 개수로 검사하면
옳은 교정을 막는다 (실측으로 확인).

색이 **늘어나는 건** 허용한다 — 오타(`빨깐`)를 제대로 고쳐 색으로
인식된 경우다. 단 원문에 색 비슷한 낌새조차 없으면 거부한다.

회귀 검사 15개(고쳐야 할 것 3 + 건드리면 안 될 것 12) 전부 통과.

## 데이터를 Gemma 로도 만든다

규칙(`fixer/gen_data.py`)만으로는 오염이 너무 정형화된다. 모델이 그 규칙만
외워서, 조금만 다른 오염이 오면 손도 못 댄다 (실측: 새 형태 5개 중 **0개** 교정).

그래서 **DGX Spark 의 Gemma** 에게도 오염을 만들게 했다 (`fixer/gen_gemma.py`).
Gemma 는 실제 음성인식이 어떻게 틀리는지 알아서, 같은 문장도 매번
다르게 틀려 준다:

```
열어   -> 열어어      (어미 늘어짐)
가     -> 가아
잡아   -> 잡어
도킹으로 -> 도킹이로   (조사 오류)
옮겨줘 -> 옮겨주       (어미 잘림)
그거   -> 그 그걸      ('그' 가 여기저기)
파란   -> 파랖
```

이 패턴을 규칙 생성기에도 반영했다(`add_tail_slur`, `add_josa_slip`,
`add_geu`). 섞어 학습하니 새 형태 교정이 **0/5 → 3/5** 로 올랐다.

Gemma 데이터 1,526 건은 `fixer/gemma_data.jsonl` 에 있다.
(LLM 왕복이 느려 많이 못 모았다 — 더 모으면 더 나아질 여지가 있다)

## 학습 데이터의 균형이 전부였다

처음엔 '고칠 게 없는' 예가 **3.5%** 뿐이었다. 그랬더니 모델이
*"입력이 오면 무조건 뭔가 고쳐야 한다"* 고 배워서, 2에폭째에
멀쩡한 말까지 망가뜨렸다 (`"하강"` → `"하하강"`).

**깨끗한 예를 35% 로 올리고**, 오염의 세기도 섞었다
(약함 35% / 보통 25% / 강함 30% / 아주 강함 10%).
전에는 97% 가 겹침 중복이라 모델이 "중복 지우기" 만 배우고
다른 오염엔 약했다.

바꾼 뒤로는 에폭을 더 돌려도 안 망가진다.

## 에폭은 적을수록 좋았다

검증 손실은 에폭마다 계속 떨어지는데(0.0089 → 0.0011), **실제 성능은
1~2 에폭이 제일 좋았다.** 데이터가 규칙으로 만든 것이라 금방 외워져서,
더 돌리면 학습 데이터에만 맞고 새 오염엔 약해진다.

| 에폭 | 검증 손실 | 회귀 15개 | 새 형태 5개 |
|---|---|---|---|
| **1** | 0.0039 | **15/15** | **3/5** ← 채택 |
| 2 | 0.0020 | 15/15 | 1/5 |
| 4 | 0.0012 | 14/15 | — |

그래서 **검증 손실만 보고 고르면 안 된다.** `fixer/test_fixer.py` 로
실제 문장을 돌려 보고 골라야 한다.

## 만들면서 겪은 것

- **어텐션이 느렸다** — `nn.MultiheadAttention` 에 마스크를 주면
  최적화 경로를 못 타서 GB10 에서 스텝당 1,972ms 가 나왔다.
  `scaled_dot_product_attention(is_causal=True)` 로 바꿔 1,310ms.
  수식은 완전히 같다. (옛 체크포인트는 `in_proj_weight` → `qkv.weight`
  이름만 바꾸면 그대로 쓸 수 있다)
- **CPU 는 11배 느리다** — 배치256 환산으로 GPU 1.97초 vs CPU 22.8초.
