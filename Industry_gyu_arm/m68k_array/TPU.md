# 자작 TPU — 시스톨릭 배열을 IC 로 만들기

**2026-09-14. 2×2 는 39,920원, 4×4 는 159,680원.**

RACHEL 을 68000 32노드로 돌리려다 **통신 병목**에 막혔다.
그 문제를 구글이 어떻게 풀었는지 보니 답이 시스톨릭 배열이었고,
ROM 을 곱셈표로 쓰면 74HC 만으로 만들 수 있다는 것을 알았다.

---

## 0. 왜 TPU 인가 — 통신 병목

32노드 CPU 클러스터를 계산해 보면 이렇게 된다:

| 방식 | 계산 | 통신 | 합계 | 가속 |
|---|---|---|---|---|
| 단일 칩 | 14.2초 | 0 | 14.2초 | 1.0배 |
| **행 분할 32노드** | 0.44초 | **70.2초** | 70.7초 | **0.20배** |
| 층 분할 8노드 | 1.77초 | 1.1초 | 2.8초 | 5.0배 |

**32개가 1개보다 5배 느리다.** 노드가 늘수록 뿌리고 모으는 양이 폭발한다.
토큰당 640KB, 문장당 81MB, 동기화 4,160회.

### TPU 는 통신을 배선으로 바꾼다

```
클러스터:  노드0 계산 → 결과를 링에 실어 → 노드1 이 받음
           ↑ 전선 수십 cm, 프로토콜, 버퍼, 대기

시스톨릭:  칸(0,0) → 부분합을 바로 아래 칸(1,0) 으로
           ↑ 배선 한 가닥, 클럭 하나에 이동
```

구글 TPU v1 은 256×256 MAC 격자다. 확인한 자료:

> 각 가중치를 **256번 재사용**하고 각 활성값도 **256번 재사용**하면서
> **메모리 접근이 없다.** 128×128 행렬곱을 **128사이클**에 끝낸다 —
> CPU 는 캐시 미스 때문에 수천 사이클.

**다만 TPU 가 통신을 없앤 것은 칩 안쪽 층뿐이다.**
칩↔메모리(그래서 HBM), 칩↔칩(그래서 ICI 전용 링크)은 그대로 남는다.

## 1. PE — 처리 요소 하나

매 클럭마다 하는 일이 이것뿐이다:

```
      x_in
       ↓
   ┌─────────────────────────┐
 x→│  w (래치에 고정)          │→ x_out    x 를 오른쪽으로
   │  psum_in + w*x = psum    │
   └──────────┬──────────────┘
              ↓ psum_out                  부분합을 아래로
```

1. 왼쪽에서 x 를 받는다
2. 자기 가중치 w 와 곱한다
3. 위에서 내려온 부분합에 더한다
4. x 는 오른쪽으로, 부분합은 아래로 넘긴다

**전부 래치에 물려 있어 한 클럭에 한 단계씩 흐른다.**
프로그램 카운터도 명령 해석기도 없다 — 이게 CPU 와의 근본 차이다.

## 2. 핵심 아이디어 — 곱셈을 ROM 으로

74HC 로 8×8 곱셈 회로를 짜면 칩 15~20개가 든다.
**룩업 테이블을 쓰면 ROM 하나면 된다.**

```
8비트 × 8비트 = 65,536 조합
결과를 16비트로 저장 → 128KB

주소  A0~A7  = x (활성값)
      A8~A15 = w (가중치)
출력  D0~D15 = x * w

→ SST39SF010 (128KB) 하나가 8×8 곱셈기
→ 읽기 70ns = 14MHz 동작
```

**이미 사려던 부품이다.** 부트 ROM 으로 쓰려던 SST39SF010 이 곱셈기가 된다.
그리고 5V 로 구우므로 아두이노 MEGA 로 바로 굽는다.

### 정밀도 — 8비트로 줄인다

RACHEL 의 활성값은 Q15(16비트)인데, ROM 주소가 8비트뿐이다.

| 방식 | ROM | PE 값 | 정밀도 |
|---|---|---|---|
| x 를 8비트로 | 1개 | **9,980원** | 상대오차 약 0.4% |
| x_hi·x_lo 분할 | 2개 | 14,010원 | 16비트 유지 |

**8비트로 줄이는 쪽을 기본으로 한다.** 다만 8층을 거치면 오차가 어떻게
쌓이는지 `verify_dusk.py` 로 확인해야 한다 — 아직 안 했다.

`SHIFT.md` 의 교훈: *"커널 하나씩은 맞는데 8층을 거치면 어긋난다."*

## 4. 배열 전체 부품표

PE 외에 배열마다 필요한 것:

| 부품 | 2×2 | 4×4 | 8×8 | 단가 | 역할 |
|---|---|---|---|---|---|
| **PE** | 4 | 16 | 64 | 9,980 | 위 표 |
| 14MHz 오실레이터 | 1 | 1 | 1 | 1,600 | 배열 전체가 하나를 공유 |
| 74HC244 클럭 분배 | 1 | 2 | 8 | 700 | **스큐 방지** |
| 74HC574 입력 래치 | 2 | 4 | 8 | 700 | x 를 배열에 밀어넣기 |
| 74HC574 출력 래치 | 2 | 4 | 8 | 700 | psum 받기 |
| 74HC138 제어 디코더 | 1 | 1 | 1 | 700 | 호스트 명령 해석 |
| 0.1µF 커패시터 | 22 | 58 | 202 | 30 | **칩마다 1개** |
| 10µF 전해 | 4 | 4 | 4 | 50 | 전원 안정 |
| 10kΩ 저항 | 20 | 20 | 20 | 10 | 풀업 |
| 만능기판 | 1 | 2 | 8 | 5,000 | |
| 전원 5V 2A | 1 | 1 | 1 | 15,000 | |

### 합계

| 배열 | PE | **총액** | 320×320 행렬곱 | MAC/s | 납땜 핀 | 용도 |
|---|---|---|---|---|---|---|
| **2×2** | 4 | **66,780원** | 585 ms | 56M | **약 800** | **원리 증명** |
| **4×4** | 16 | **196,120원** | 146 ms | 224M | 약 2,900 | 데모 가능 |
| 8×8 | 64 | 719,280원 | 37 ms | 896M | **약 11,400** | 실용 |

**2×2 부터 만든다.** PE 가 전부 동일하므로 4×4 는 복사 작업이다.

**8×8 은 납땜 11,400핀으로 68000 32노드(9,000핀)를 넘는다.**
거기까지 가려면 PCB 가 필요하다.

### 2×2 구조

```
     x0 →  [PE00] → [PE01] → x0
            ↓        ↓
     x1 →  [PE10] → [PE11] → x1
            ↓        ↓
          psum0    psum1
```

**확인할 것 넷:**
- 클럭마다 데이터가 한 단계씩 흐르는가
- ROM 곱셈표가 맞는가
- 부분합이 제대로 누적되는가
- 클럭 스큐가 문제없는가

## 5. 다른 방식과 비교

| | 값 | 성능 | 납땜 | 만드는 것 | 통신 |
|---|---|---|---|---|---|
| 68000 32노드 | 563,068원 | 7.2분/문장 | 9,000핀 | CPU 클러스터 | **병목** |
| STC32G 32노드 | 255,800원 | 6.9초/문장 | 2,500핀 | CPU 클러스터 | 병목 |
| **4×4 TPU** | **196,120원** | **146ms/행렬곱** | 2,900핀 | **시스톨릭 배열** | **없음** |
| **2×2 TPU** | **66,780원** | 585ms/행렬곱 | **800핀** | 시스톨릭 배열 | 없음 |
| 8×8 TPU | 719,280원 | 37ms/행렬곱 | 11,400핀 | 시스톨릭 배열 | 없음 |

**주의: 단위가 다르다.** CPU 클러스터는 문장 하나(13.3억 MAC) 기준이고,
TPU 는 행렬곱 하나(320×320) 기준이다. 문장 하나에 행렬곱이 수천 번 들어가므로
**TPU 만으로 문장을 처리하려면 호스트가 그 사이를 메워야 한다** (6절 참조).

**TPU 의 장점은 값이 아니라 구조다:**
- 통신이 배선이라 없다 — 노드를 늘려도 병목이 안 생긴다
- 곱셈이 ROM 하나로 끝난다 — 74HC 15~20개를 대체
- 보드가 한 장이라 전원·클럭·소켓이 N배로 늘지 않는다

## 6. 호스트가 필요하다

**TPU 는 행렬곱만 한다.** 나머지는 CPU 가 해야 한다:

```
TPU 가 하는 일:   y = W · x        (행렬곱)
호스트가 하는 일:  LayerNorm, GELU, softmax, KV캐시, 토큰 선택
```

`dusk_rachel.c` 에서 `ra_mv()` 만 TPU 로 보내고 나머지는 그대로 둔다.
**코드 구조가 이미 그렇게 되어 있다** — `dusk.h` 에 `DUSK_MATVEC` 명령이
정의돼 있고, 행렬곱을 노드에 던지는 구조다.

**호스트로 68000 을 쓰면 낭만도 살아난다.**
"1979년 CPU + 자작 TPU" 가 된다.

## 7. 아직 확인 안 된 것

- [ ] **8비트 정밀도가 8층을 견디는가** — PC 에서 `verify_dusk.py` 로 먼저 확인.
      이게 안 되면 ROM 2개 방식(14,010원/PE)으로 가야 한다
- [ ] **클럭 스큐** — 모든 PE 가 같은 클럭에 움직여야 한다. 2×2 는 괜찮을
      것 같지만 8×8 부터는 클럭 분배 회로(74HC244 트리)가 필요하다
- [ ] **ROM 70ns 로 14MHz 가 실제로 나오는가** — 래치 지연까지 더하면 더 느릴 수 있다
- [ ] **가중치를 어떻게 먹이는가** — 4×4 가 224M MAC/s 면 가중치도 초당 224MB
      필요. 병렬 SRAM 뱅크 여러 개가 필요할 수 있다
- [ ] **호스트 ↔ TPU 인터페이스** — 명령·데이터를 어떻게 주고받을지
