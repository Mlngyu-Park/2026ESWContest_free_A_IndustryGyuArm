# M68K-GPU — MC68000 32개 병렬 어레이

1979년 프로세서 32개를 묶어 GPU처럼 쓰고, 그 위에서 RACHEL(자작 LLM)을 돌린다.

성능이 목적이 아니다. 노트북 한 대가 0.14초에 하는 일을 32개가 3.8분에 한다.
**병렬 컴퓨팅의 원리를 눈으로 보여주는 것**이 목적이다.

---

## 1. 왜 68000인가

Z80·6502와 비교해 고른 결과다.

| | Z80 (1976) | 6502 (1975) | **68000 (1979)** |
|---|---|---|---|
| 곱셈 명령 | 없음 (560사이클) | 없음 (200사이클) | **MULS 70사이클** |
| 주소공간 | 64 KB | 64 KB | **16 MB** |
| 데이터 폭 | 8비트 | 8비트 | **16비트** |
| 32개 소요 | 42분 | 30분 | **3.8분** |
| 모델 9.6MB | 뱅크 스위칭 필수 | 뱅크 스위칭 필수 | **칩당 305KB 통째로** |
| 수급 (2026) | 2024년 단종·위조 심각 | 신품 유통 | 재고품, 개당 3,260원 |
| 핀 수 | 40 | 40 | 64 (배선 부담) |

**결정 요인은 주소공간이다.** 16MB면 각 노드가 자기 몫 가중치를 통째로 들고
있을 수 있다. Z80·6502는 64KB뿐이라 뱅크 스위칭 회로를 노드마다 달아야 하고,
그러면 회로 복잡도가 두 배가 된다.

곱셈 명령이 있다는 것도 크다. 신경망 계산은 곱셈-누산(MAC)의 반복인데,
Z80은 곱셈기가 없어 시프트·덧셈 루프로 560사이클을 쓴다.

## 2. 사양

### 성능

```
모델          RACHEL 10M 파라미터 (int8, 9.6 MB)
출력          블록 JSON 평균 58글자
총 연산       5.83억 MAC
MAC 비용      약 100 사이클 (MULS 70 + 로드·누산·루프)

1개  8MHz    →  121분
32개 8MHz    →  3.8분      ← 목표
32개 12MHz   →  2.5분
32개 16MHz   →  1.9분
```

### 노드당 메모리

```
가중치 (9.6MB ÷ 32)     305 KB
활성값·스택·코드          약 32 KB
─────────────────────────────
합계                    약 340 KB

SRAM 512KB 로 충분하나, 1MB 를 권장한다.
3만원 더 쓰면 모델을 2배(20M)로 키워도 보드를 안 뜯는다.
```

### 확장 여유

| 모델 크기 | 칩당 메모리 | 32개 소요 | 판정 |
|---|---|---|---|
| 10M (지금) | 305 KB | 3.8분 | 최적 |
| 20M | 610 KB | 7.6분 | 가능 |
| 50M | 1.5 MB | 19분 | 전시엔 김 |
| 2B (Gemma급) | 60 MB | 12.6시간 | 불가 |

주소공간 상한은 이론상 5억 파라미터지만, **시간이 먼저 막힌다.**

## 3. 아키텍처 — 메시지 패싱 링

```
[PC]  시리얼(USB)
  │
[마스터 68000]  문장 파싱 · 작업 분배 · 결과 취합
  │
  ├─ 링 →  [워커 0] → [워커 1] → ... → [워커 31] →┐
  └──────────────────────────────────────────────┘
```

### 공유 버스를 쓰지 않는 이유

역사가 답을 준다.

- **ZMOB** (1979, 메릴랜드대, Z80A 256개): 공유 메모리를 포기하고
  48비트 폭 시프트 레지스터 링("conveyor belt")으로만 통신
- **ZedRipper** (2019, FPGA Z80 16코어): 40년 뒤에도 같은 결론 — Z-Ring
- 6502 커뮤니티 결론: 공유 버스는 **2개가 한계**, 그 이상은 중재 오버헤드로
  오히려 느려진다

32개를 하나의 버스에 물리면 각자 1/32의 시간만 얻는다. 병렬화의 의미가 사라진다.

### 노드 구성

각 노드는 독립된 소형 컴퓨터다.

```
68000P8 (8MHz)
  ├─ SRAM 1MB        자기 몫 가중치 + 작업공간
  ├─ 부트 ROM        기동 코드 (또는 링으로 주입)
  ├─ 링 IN/OUT       앞뒤 노드와 시리얼 연결
  └─ LED             계산 중 표시
```

노드끼리 주소·데이터 버스를 공유하지 않으므로:
- 버스 경합 없음
- 노드 하나가 죽어도 나머지가 산다
- 배선이 노드당 몇 가닥으로 끝난다
- 클럭 동기가 필요 없다 (각자 자기 클럭)

## 4. 계산 분배

행렬-벡터 곱을 행 단위로 32등분한다.

```
y[i] = Σ_j  W[i][j] · x[j]

워커 k 는 i ≡ k (mod 32) 인 행만 계산한다.
→ 각 워커가 W 의 1/32 만 갖고 있으면 된다 (305KB)
```

한 글자 생성 흐름:

```
1. 마스터가 입력 벡터 x 를 링으로 뿌린다        (320 × 2바이트)
2. 각 워커가 자기 행들의 MAC 을 돈다            ← 여기가 3.8분의 대부분
3. 워커가 결과를 링으로 되돌린다
4. 마스터가 합쳐 다음 글자를 정한다
5. 58번 반복
```

## 6. 주의할 점

### 부품
- 알리 "신제품" 표기는 믿지 말 것. 68000은 신규 생산이 없다 — 재고품이거나
  회수품이다. **여유분 2~3개를 더 살 것**
- DIP-64는 핀이 많다. 32개면 핀 2,048개다. 소켓을 쓰고 납땜을 신중히

### 설계
- 4레이어 PCB 권장 (전용 그라운드 플레인)
- 칩마다 0.1µF 디커플링 커패시터를 전원 핀 바로 옆에
- 노드마다 상태 LED + 시리얼 — **디버깅 수단이 없으면 32개 중 어느 게
  문제인지 찾을 수 없다**
- 부트 코드를 32개 ROM에 각각 굽는 건 비현실적. 마스터가 링으로 주입하는
  부트로더를 먼저 만들 것 (ZMOB도 VAX 호스트가 이 역할을 했다)

### 순서
**32개를 한 번에 만들지 말 것.**

```
1. 에뮬레이터로 소프트웨어 완성       ← 보드 없이, 비용 0
2. 4노드 시제품 (약 5만원)           ← 통신·동기화 검증
3. 32노드 확장
```

4노드가 안 되면 32노드도 안 된다. 4노드가 되면 32노드는 복사 작업이다.
