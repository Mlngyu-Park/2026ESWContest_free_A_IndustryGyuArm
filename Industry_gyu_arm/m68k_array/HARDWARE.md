## 1. 지켜야 할 원칙 — 사용자가 명시한 것

이 문서의 모든 결정은 아래 원칙에서 나왔다. 값이 싸다는 이유로 어겨서는 안 된다.

### 「낭만」— FPGA 는 불합격이다

> 내가 원하는 건 FPGA 방식이 아니야 절대로. 다만 납땜 그리고 IC 집적회로로만
> 구성된 PC 를 만들고 싶은 거라고. 만약 가격만 생각해서 FPGA 쓴다면 '낭만' 불합격이야.
> 그럴 거면 라즈베리 파이에 올려버리지.

FPGA(TG68 코어)로 하면 4노드가 12만원, 32노드도 훨씬 싸다. 속도도 빠르다.
**그런데 그건 68000 을 만드는 게 아니라 68000 인 척하는 코드를 다운로드하는 것이다.**

같은 이유로 STM32(1,848배 빠름)와 ATmega(27.5배)도 탈락이다.
STM32 는 DIP 가 없어 개발보드를 전선으로 잇는 형태가 되고, ATmega 는
SRAM·ROM·클럭·리셋이 전부 내장이라 "IC 를 조립한다"는 감각이 사라진다.

### 실물 IC 로만, 납땜으로

만능기판 + 플럭스 + 납 + 전선은 이미 갖고 있다. 여기에 꽂을 **DIP 패키지 부품**만 산다.
표면실장(TSOP/QFP/BGA)은 쓰지 않는다 — 유일한 예외가 SPI 플래시(SOIC-8)인데,
핀이 8개뿐이라 변환기판에 붙이기 쉽다.

### 모델은 못 줄인다

> 모델 사이즈는 못 줄인다.

RACHEL v9 (9.66MB) 를 그대로 돌린다. 재학습으로 가중치를 줄이는 방법은 쓰지 않는다.

## 2. 값을 어떻게 낮췄나 — 231,040 → 89,186원

| 단계 | 무엇을 | 절약 |
|---|---|---|
| ① | TL866 프로그래머 → **아두이노 MEGA 보유** | **70,000** |
| ② | 병렬 EPROM 20개 → **SPI 플래시 1개** | **19,800** |
| ③ | 노드 SRAM 5개(가중치용) → **2개(작업용)** | **약 24,000** |
| ④ | 소켓 단가 국내가 → **알리 실측가** | **약 29,000** |
| ⑤ | SPI 128MB → **16MB** | **7,000** |
| ⑥ | 12.75V EPROM → **5V 플래시** | 승압회로 제거 |
| | **합계** | **약 142,000원** |

### ① 프로그래머 — 사용자가 이미 갖고 있었다

> 내가 아두이노 메가를 갖고 있는 것을 너는 모르고 있는 거 같아.

SST39SF040 은 **5V 로 굽는다**. 아두이노 MEGA 는 디지털 핀이 54개라
주소 19 + 데이터 8 + 제어 2 = 29핀을 **시프트 레지스터 없이 직접** 연결할 수 있다.
GitHub 에 검증된 프로젝트가 넷 이상 있다 (`doctorandrey/39SF040_Programmer` 등).

**TL866II Plus 70,000원이 통째로 빠졌다.**

덤으로 EPROM(AM27C040, 12.75V) 대신 플래시(5V)를 쓰게 되어
MT3608 승압모듈과 UV 지우개(40,000원)도 필요 없어졌다.
잘못 구워도 몇 초 만에 다시 굽는다 — 첫 하드웨어 프로젝트에서 이게 크다.

### ② 병렬 → 직렬 (SPI) ← 가장 큰 구조 변화

이게 값을 낮춘 진짜 이유다. 사용자가 정확히 물었다:

> 가격이 드라마틱하게 떨어진 이유가 뭐냐고.

**용량 때문이 아니라 패키지 때문이다.**

| | 병렬 EPROM | 직렬 SPI |
|---|---|---|
| 데이터 핀 | 8개 | **1개** |
| 주소 핀 | 19개 | **0개** (명령으로 전달) |
| 총 핀 | 32개 | **8개** |
| DIP 최대 용량 | 512KB | — |
| SOIC-8 최대 | — | **128MB** |
| **1MB당 값** | **2,180원** | **125원** |

핀이 적으니 같은 크기 칩에 훨씬 많이 담긴다. 그래서:

```
병렬: 노드당 5개 × 4노드 = 20개, 21,800원
직렬: 전체가 1개        =  1개,  2,000원
```

**"노드마다 5개" → "전체가 하나"** 가 된 것이 값의 대부분이다.
병렬은 주소선 19가닥을 공유하려면 버스 중재가 필요한데, SPI 는 4가닥뿐이라
공유가 쉽다. 그리고 68000 이 느려서 대역폭이 남는다 (아래 4절).

### ③ 노드 SRAM — 가중치를 안 담으니 작아졌다

병렬 EPROM 시절에는 노드마다 가중치 2.34MB 를 들고 있어야 해서
AS6C4008(512KB) 5개가 필요했다. SPI 스트리밍으로 바꾸니
**노드는 작업버퍼 15.7KB 만** 있으면 된다 → 62256(32KB) 로 충분.

### ④ 소켓 단가 — 사용자가 실물을 찾아왔다

DIP-64 소켓을 개당 2,000원으로 잡았는데, 알리 실제 가격은 **10개 3,480원 = 개당 348원**.
6분의 1이었다. 다른 소켓·74HC·수동부품도 같은 비율로 내려갔다.

> 소켓 같은 거는 빼 괜히 쓸데없이 길어진다.

이후 표에서는 소켓을 일괄 항목으로 묶었다.

### ⑤ SPI 용량 — 128MB 는 과했다

사용자가 "차라리 오버해서 100MB 로 설계하자"고 해서 W25Q01JV(128MB, 9,000원)를 넣었는데,
곧바로 되물었다:

> 만약 128이 용량이 커서 하나만 사용해도 된다는 이유라면 16mb 를 사용해도 되는 거잖아.

맞다. 담을 것은 9.64MB 다. **W25Q128(16MB, 2,000원)이면 충분**하다.
값이 떨어진 이유는 용량이 아니라 "20개 → 1개" 였으므로, 16MB 로도 같은 효과다.

## 3. CPU 선정 — 왜 68000 인가

사용자가 여러 번 되물었다:

> 68000 말고 대체 없냐 진짜로 · 32비트도 괜찮으니까 · Z80 이후 대표적인 IC CPU 부터 찾아보는 거야

노드 CPU 가 반드시 만족해야 할 조건 넷:
**① DIP 패키지 ② 하드웨어 곱셈기 ③ 외부 메모리 버스 ④ 주소공간**

> 최대 64개**였기 때문이다. — 위키피디아

진짜 32비트 버스(데이터32+주소32)는 DIP 에 안 들어간다. 그래서 32비트 CPU 는
전부 PGA·PLCC 로 갔다. **"납땜 가능 + 최고 성능"의 답이 68000 이다.**

### 유일한 실질 대안 — NEC V30

곱셈이 **24T** 로 68000(54T)의 절반 이하다. NEC 가 8086 을 복제하며 곱셈 회로를
새로 설계했다 (8086 은 128T). DIP-40 이라 핀도 24개 적다.

| | MC68000 | NEC V30 |
|---|---|---|
| 32노드 시간 | 7.2분 | **3.8분** |
| 값 | 2,470원 | 4,000원 |
| 주소공간 | 16MB | **1MB** |
| 주소·데이터 | 분리 | **멀티플렉스** (74HC373 3개 추가) |
| 자작 자료 | 많음 | 거의 없음 |

**68000 을 유지한다.** 1.9배 빠르지만 자작 자료가 없고 회로가 복잡해진다.
4노드는 시제품이라 시간이 중요하지 않다. 32노드에서 재검토할 가치는 있다.

### 정정 기록

초기 표에 **V30/V20 주소공간을 16MB 로 잘못 적었다.** NEC 사용자 매뉴얼 확인 결과
**20비트 주소 버스로 1MB** 가 맞다. 또 **68000 MUL 을 70T 고정으로 적었는데**
모토로라 매뉴얼 기준 **38+2n, 70T 는 최대값**이다 (평균 ~54T).

## 4. 저장장치 선정 — 왜 SPI 인가

기준: 68000 하나가 필요로 하는 대역폭 **80 KB/s** (MAC 하나 11µs, 바이트당 1 MAC)

| 저장장치 | 용량 | 대역폭 | 탐색 | 4노드 값 | 판정 |

| AM27C040 EPROM ×20 | 512KB | 14MB/s | ~0 | 21,800 | △ 12.75V |

### SPI 가 되는 이유 — 코드가 순차 접근이다

`dusk_node.c` 의 `dusk_mac_row()` 는 가중치를 `w[0], w[1], w[2]...` **순차로만** 읽는다.
되돌아가지 않는다 — 스트리밍이다.

그래서 가중치를 SRAM 에 통째로 올릴 필요가 없다. 읽으면서 바로 계산하고 버리면 된다.
**필요한 버퍼는 640바이트(더블버퍼링)뿐**이다.

그리고 **68000 이 느려서** SPI 로도 충분하다:

| 방식 | 대역폭 | 여유 |
|---|---|---|
| 병렬 EPROM | 14,000 KB/s | 175배 |
| **SPI 8MHz** | **1,000 KB/s** | **12배** |
| SPI 비트뱅잉 2MHz | 250 KB/s | 3배 |

**32노드는 8노드씩 4그룹으로 나눈다** (12.5노드까지만 공유 가능).
각 칩에는 **같은 내용**이 들어간다 — 용량을 나누는 게 아니라 대역폭을 나누는 것이다.

### 플로피가 안 되는 이유

사용자가 물었다: *오래된 엄청 옛날의 플로피는 어때.*

낭만으로는 최고다. 그리고 **68000 이 느려서 속도가 거의 맞는다** (플로피 읽기 10.8분,
68000 계산 8.2분). 그런데 셋이 막는다:

- **대역폭 62.5KB/s** 로 필요량(80KB/s)에 못 미친다
- **트랙마다 탐색 100ms** — 32노드 기준 8분 추가 (총 18분)
- **노드당 16,500원** (드라이브+FDC컨트롤러+디스켓) = EPROM 의 15배

**단, 마스터의 부팅 디스크로는 좋다** — 13,000원에 전시 효과가 크고 성능에 영향 없다.

## 5. shift 모델 — 두 가지를 구분해야 한다

「shift」라는 말이 두 의미로 쓰였다. 섞으면 안 된다.

### ① SHIFT.md 가 한 것 — **완료됨**

**실수 연산을 전부 정수로 바꿨다.** 시프트 명령을 쓴 게 아니다.

| 실수 연산 | 정수 대체 | 68000 비용 | 오차 |
|---|---|---|---|
| `pow(2, shift)` | 시프트 한 번 | ASL/ASR | **0** |
| `/ sqrt(hd)` | Q15 상수 곱 | MULS 1회 | 0.003% |
| `exp()` | 2의 거듭제곱 분해 + 16칸 표 | 시프트 + MULS | 0.12% |
| `tanh()` (GELU) | 512칸 표(1KB) + 선형보간 | MOVE.W + MULS | 0.008% |
| `sqrt()` | 뉴턴법 정수 제곱근 | DIVS 몇 회 | 0.00009% |

**결과: 한 문장 77분 → 8.2분 (9.4배).** 정확도는 Spark 200문장 98.5%.

68000 에 FPU 가 없어서 실수 덧셈 하나가 316사이클(정수의 39배)이었다.
**이게 진짜 필요했던 작업이고, 이미 끝났다.**

가중치 크기는 **안 줄었다** (int8 9.38MB 그대로). `MULS` 도 유지한다.

### ② 가중치를 2의 거듭제곱으로 — **하지 않는다**

팀원이 제안한 별개 작업이다. 실제 `rachel.bin` 을 400만개 샘플링해 검증했다:

```
지수 분포: 0~7 (8종) → 3bit + 부호 1bit = 4bit 에 정확히 맞음
가중치 9.38MB → 4.69MB (절반)
반올림 오차: 개별 평균 16.7%, 최대 40.7%
```

**68000 에서 얼마나 빠른가 — 사이클 단위로 쟀다:**

| 방식 | MAC | 4노드 | 32노드 |
|---|---|---|---|
| MULS (지금) | 88T | 59.4분 | 7.2분 |
| shift (4bit) | 62T | 41.7분 | 5.1분 |
| | | | **1.43배** |

기대보다 작다. 이유 셋:

- **68000 에 배럴 시프터가 없다.** `ASL.L #n` 은 `6+2n T` — 1비트씩 민다.
  실측 평균 시프트량이 4.87 이라 ASL 평균 **15.7T**
- **4bit 압축을 푸는 데 비용이 든다.** 니블 분리(`AND`,`LSR`) + 부호 분기 = 가중치당 15~22T
- **MULS 가 생각보다 싸다.** int8 은 상위 비트가 0 이라 평균 ~54T

**결론: 지금 구조에서는 굳이다.**

- **부품이 안 줄어든다** — SPI 16MB 하나에 9.38MB든 4.69MB든 다 들어간다
- **정확도 재검증에 며칠** — 98.5% 를 만드는 데 버그 11개를 잡았는데 여기에 곱셈 오차를 새로 넣는다
- **32노드에서 2분 차이** — 전시용인데 의미가 작다

**단, SRAM preload 구조로 간다면 의미가 크다** (노드당 2.34MB → 1.17MB, 4.8만원 절약).

## 6. 메모리 소요 — v9 기준 실측

모델 v9: `d=320 L=8 H=8 어휘=448 문맥=179`, 파일 9.66MB

### 성격이 여섯이다. 섞으면 안 된다

## 8. 왜 만능기판은 4노드까지인가

| | 4노드 | 32노드 |
|---|---|---|
| 납땜 핀 | 1,900개 | 9,000개 |
| 기간 | 주말 며칠 | 하루 8시간씩 몇 주 |

**32노드가 어려운 이유 넷:**

- **납땜 양** — 핀 하나에 10초면 25시간. 배선 확인·수정은 별도
- **실수 찾기** — 33장 중 한 장이 안 되면 그 장의 200가닥을 다 짚어야 한다
- **신호 품질** — 8MHz 는 125ns 마다 신호가 바뀐다. 공중 배선은 노이즈·반사가 생기고,
  접지가 갈라져 전압이 흔들린다. PCB 는 그라운드 플레인으로 해결된다
- **재현성** — 32장을 손으로 만들면 장마다 미묘하게 달라지고, 그게
  "왜 17번 노드만 가끔 틀리지?" 가 된다

**4노드가 되면 그 회로를 그대로 PCB 로 옮기면 된다.**

## 9. 부품 살 때 주의

### 68000 은 위조가 실제로 있다

1996년 단종품이라 파는 건 전부 재고품 아니면 회수품이다. 확인된 사례:

- **MC68HC000P-16 표시인데 실제로는 P-8** 이었던 사례
- 원래 각인을 사포로 갈고 레이저로 다시 새김 (각인 품질이 나빠 알아볼 수 있음)

**대응:** **P8 을 사라** — 위조는 주로 빠른 등급(P12·P16)으로 속인다. P8 은 속일 이유가 없다.
예비 2개 이상. 각인이 흐리거나 표면이 유난히 매끈하면 의심.

**라이센스 생산품도 있다** (짝퉁 아님): 히타치 HD68000, 톰슨 TS68000, 도시바 TMP68000,
시그네틱스 SCN68000, 모스텍 MK68000, 록웰 R68000. 전부 핀 배치·명령어 동일.
다만 값은 비슷하거나 오히려 비싸다 (히타치는 수집가 수요로 더 비쌈).

### 규격

- **DIP-64 소켓** — 68000 은 2.54mm 피치 / 0.9인치(22.86mm) 행간격.
  알리에 1.778mm 라고 적힌 것이 있으니 판매자 확인 필요
- **62256 은 DIP-28** — 32KB 라 주소선 15개. DIP-32 아님
- **SST39SF040 DIP-32 는 2027년 1월 단종 예정** — 재고 확인 후 구매

### 구매처

| 곳 | 무엇을 | 배송 |
|---|---|---|
| 알리익스프레스 | 68000, 소켓, 74HC, 오실레이터, W25Q128, 수동부품 | **7~9주** |
| 디바이스마트 | AS6C4008 (DigiKey 정품, 위조 없음) | 4~5일 |
| 국내 부품점 | 저항·커패시터·LED (금액 작고 자주 씀) | 1~2일 |

**알리 배송이 7~9주**다. 주문을 먼저 넣고 기다리는 동안 회로를 익히는 게 시간을 아낀다.

## 10. 아직 확정 안 된 것

- [ ] **프로그램 코드 크기** — 16KB 는 추정. `gcc-12-m68k-linux-gnu` 로 실측 필요.
      노드 SRAM 이 딱 32KB 라 여유 0 이므로, 코드가 크면 62256 이 더 필요하다
- [ ] **코드를 SRAM 에 복사해야 하나** — 68000 은 ROM 에서 직접 실행할 수 있다.
      복사가 불필요하면 62256 을 노드당 1개로 줄인다 (4노드 6,000원 절약)
- [ ] **74HC 개수** — 노드 보드는 칩이 4개뿐(68000·부트ROM·SRAM 2개)이라
      74HC138 의 8출력 중 4개만 쓴다. 실제 회로를 그려야 3개로 줄일 수 있는지 안다
- [ ] **노드가 SPI 를 어떻게 받는지** — 보드마다 버퍼가 필요할 수 있다
- [ ] **MAC 사이클 88T** — 손계산이다. `SHIFT.md` 가 경고했듯 실제 68000 칩으로
      재본 적이 없다. 전시에서 "7분"이라고 단언하면 안 된다

## 11. 다음 단계

```
1단계  68000 하나 살리기          LED 깜빡이면 성공
2단계  4노드 + 링 통신            답이 나오면 성공 (약 60분)
3단계  32노드                     PCB 필요
```

**필요한 회로 개념 셋:**

- **리셋 회로** — 전원 켤 때 `/RESET` 과 `/HALT` 를 **100ms 동안 같이** 눌러야 한다.
  `/RESET` 만 누르면 안 된다. NE555 가 이 일을 한다
- **주소 디코딩** — "0번지는 부트ROM, 0x080000 부터는 SRAM..." 을 74HC138 이 정한다
