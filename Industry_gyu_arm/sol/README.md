# SOL — 납땜 설계 언어 · 검증기 · 3D 뷰어

**2026-09-16 밤에 만든 것.** 만능기판 손납땜 회로를 글로 적고, 프로그램이
데이터시트 숫자로 검증하고, 3D/2D 로 보고, KiCad 로 넘긴다.

```
python3 gen_pe2.py            # AI 가 배선 → pe2.txt
python3 sol.py pe2.txt --all  # 검증 + pe2.json + pe2.kicad.net + pe2_list.txt
python3 build_viewer.py       # viewer.html (그냥 열어도 됨, GPU 없음)
python3 serve.py              # ★ 권장: 브라우저가 열리고 「검증 다시 실행」「파일로 저장」이 진짜 동작
python3 tpu.py                # TPU 전용 분석
python3 test_viewer.py --server   # 자동 시험 (모든 기능 실제로 눌러봄)
```

**지금은 WSL 파이썬만 쓴다** (사용자 지시, 2026-09-16). 윈도우 쪽 파일·프로세스는 명령 있기 전까지 건드리지 않는다.
`run.bat`/`stop.bat`/`build_exe.bat` 는 윈도우용으로 만들어 두었을 뿐이다.

## 검증기가 밤새 잡은 것

| # | 발견 | 조치 |
|---|---|---|
| 1 | **플래시 DQ 출력 VOH(min) 2.4V < 74HC283 입력 VIH(min) 3.15V** — 규격상 HIGH 보장 안 됨 (32곳) | 부품 교체 불가 조건 → **DQ 선마다 4.7kΩ 풀업 → VCC** (PE당 16개, 서랍 저항). 검증기 R11 이 풀업을 인식해 정보로 내리고, R13 이 플래시 IOL(2.1mA) 대비 풀업 전류(1.06mA)를, R8 이 전체 풀업 전류(34mA)를 계산 |
| 2 | 74HC283 캐리 지연: 내가 22ns 로 알던 값이 데이터시트 max 는 **39~46ns** | 임계경로 200→222ns 로 정정 (4.5MHz) |
| 3 | 옛 배선(layout_v2)에서 **74HC244 가 아무 데도 안 붙어 있음** (플로팅 입력 16개) | 클럭 버퍼로 실제 배선 |
| 4 | 74HC04 미사용 입력 4개 플로팅 | GND |
| 5 | 74HC74 2번 FF 미사용 → 입력 고정 필요 | D2·CP2 → GND |
| 6 | psum 상위 8비트가 MEGA 로 안 감 (R10 정보) | 의도됨 — PE 늘리면 다음 PE 로 감 |

**1번이 핵심이다.** 사람이 봤으면 "CMOS 라 그냥 되겠지" 하고 넘겼을 항목을
데이터시트 숫자 대조가 잡아냈다. 실제로는 CMOS 플래시가 CMOS 부하를 몰 때
거의 VDD 까지 올라가서 대개 동작하지만, **보장값**은 2.4V 다.
풀업 저항은 이 경우의 표준 처방이고, 갖고 있는 저항으로 된다 (4.7k 또는 10k).

## 뷰어 기능

| 기능 | 어떻게 |
|---|---|
| 3D ↔ 2D | 헤더 버튼 또는 `V`. **3D 는 WebGL(Three.js r128)** — 환경광 반사(PMREM), 그림자, 깎인 모서리 몸통, 인쇄 마킹, 어깨 꺾인 다리 + 납땜 필렛, 개뼈 저항(색띠는 값에서 계산), FR4 결 + 구리 링 기판, 광택 PVC 배선 튜브. WebGL 이 없으면 캔버스 3D 로 자동 복귀 |
| 3D 에서도 편집 | 핀·배선·칩을 **레이캐스팅**으로 집는다 — 클릭해 네트 선택, 「두 핀 잇기」도 3D 에서 됨. 배치 이동은 2D 에서 |
| 부드러운 조작 | 감쇠 궤도 카메라 + 관성, **커서가 가리키는 기판 지점으로 줌**, 오른쪽/Shift 끌기 이동, 움직일 때만 렌더 |
| 성능 | 다리·납땜점·소켓구멍·저항 몸통·색띠·세라믹 캡은 **인스턴싱**, 배선은 네트별 병합, **그림자 맵은 지오메트리가 바뀔 때만** 다시 계산(카메라 회전엔 무관). 드로우콜 약 340, 삼각형 17만. 헤더의 「저사양」= 그림자·반사 끄고 픽셀비 1 — 절반 이하 비용. 가만히 있을 때 GPU 0 |
| 실물 표현 | 소켓 핀구멍, 칩 1번 홈, 저항 **색띠(값에서 계산)**, 세라믹/전해 캡, 오실레이터 캔, 납땜 자국(뒷면), 그림자 |
| 배선 | 구멍에서 **올라와 달리다 내려오는** 점퍼선, 원통 하이라이트, 둥근 꺾임. 직선 모드는 아치 |
| 뒤집기 (뒷면) | `F` — 3D·2D 모두 |
| 회전 · 확대 · 이동 | 끌기 · 휠 · Shift+끌기 |
| 칩 이동 | 2D 에서 끌기 (2.54mm 격자 스냅) — **연결은 그대로 따라온다** |
| 칩 회전 | 2D 에서 부품 위에 마우스 두고 `R` (또는 「부품 회전」) |
| **연결 편집** | 핀 클릭 → 「두 핀 잇기」→ 다른 핀 클릭. 네트가 다르면 병합. 「핀 떼기」로 분리 |
| 검증 다시 실행 | serve.py 로 열었을 때 — 고친 회로를 sol.py 가 즉시 다시 검증 |
| 파일로 저장 | pe2.txt 를 덮어씀 (.bak 백업) |
| 선 모양 | 직선 / 직각 / 뒷면 우회 |
| 경로 직접 그리기 | 네트 선택 → 「경로 그리기」→ 2D 에서 경유점 클릭 |
| 선 색 | 그룹 옆 색상 칸 |
| 숨기기 | 칩 몸통 · 소켓 · 커패시터 · 핀 · 배선 · 전원선 · 구멍 · 이름, 부품별 |
| 네트 선택 | 핀/선 클릭 → 그 네트만 밝게, 핀 목록·전압 표시 |
| 납땜 순서 | 슬라이더로 그룹 하나씩 켜기 |
| 검증 결과 | 오른쪽 패널 (sol.py 결과 그대로) |
| SOL 내보내기 | **전체** (part·pin·color·group·route) — 그대로 pe2.txt 가 된다 |

실물 치수: 구멍 2.54mm, DIP 300mil=7.62mm / 600mil=15.24mm, 소켓 8.5mm, 칩 4mm.

## AI 와 프로그램의 분리 — 전압까지

```
gen_pe2.py (AI)  →  pin (연결) + expect (전압 예상: "이 네트는 HIGH 4.4 / LOW 0.1 일 것")
sol.py (프로그램) →  chips.txt 로 네트마다 HIGH/LOW 보장 범위·수신 여유·전류를 계산
                    → R15: AI 예상이 범위 밖이면 경고.  pe2_volt.txt 에 전체 표
tpu.py           →  둘의 임계경로가 다르면 "⚠ 다름" 을 낸다
```

지금 결과: **AI 예상 152개 중 152개 타당**. 일부러 틀린 값(전원보다 높은 HIGH, 보장값보다 높은 LOW,
풀업 하나 제거)을 넣으면 R15/R11 이 각각 잡는 것을 확인했다.
첫 실행에선 툴 쪽 모델이 틀려서(풀업 HIGH 를 정확히 5.00 으로 계산 → 폭 0 의 범위) 32개가 불일치로
나왔고, 누설전류 모델과 ±0.1V 허용을 넣어 고쳤다 — 교차검증이 **툴의 실수**도 잡은 경우.

뷰어에서 네트를 누르면 HIGH/LOW 범위 · 수신 VIH/VIL · 여유 · LOW 전류 · 풀업 · AI 예상과 타당 여부가 보인다.

## 과도현상 (R16~R22) — "왜 그런 건 계산 안 하나" 에 대한 답

SPICE 는 아니지만 공식으로 되는 건 다 넣었다. 상수는 `physics.txt` (출처 명시, ⚠가정).

| 규칙 | 공식 | 이 설계에서 나온 것 |
|---|---|---|
| R16 그라운드 바운스 | V = (L리드 + L접지선)·di/dt, di/dt = ΣC·VCC/tr ÷ (tr/2) | **바닥 GND 레일 하나에 위쪽 칩을 매달면 접지선 100mm+ → 바운스가 LOW 여유를 넘는다.** 칩 열마다 GND 버스를 깔고 10mm 안에 붙이면 해결 (수치 제시) |
| R17 디커플링 | V = (ESL + 2·거리·1nH/mm)·di/dt + Q/C | 캡을 VCC 핀 5mm 안에 |
| R18 크로스토크 | M = 2e-7·ℓ·(ln(2ℓ/s)−1), V = M·di/dt | psum 버스 155mm 평행 구간이 상한 1.2V — 사이에 GND 선 |
| R19 반사 | 임계 길이 = tr/(2·6.7ps/mm) = 373mm | 최장 279mm → 종단 불필요 |
| R20 클럭 스큐 | Δ길이 × 6.7ps/mm | 최대 85ps ≪ hold 5ns |
| R21 IR 강하 | I·R(AWG30 0.34Ω/m) | 7.9mV |

**R16 이 이 기판의 진짜 위험이었고, 설계로 풀었다.** `bus GND rows …` / `bus VCC rows …` 를 언어에 넣어
칩 열마다 전원 버스 선을 깔았다 (gen_pe2.py 가 핀 행을 모아 자동으로 정함). 결과:

| | 바닥 레일 하나 | 열마다 버스 |
|---|---|---|
| 최장 접지선 | 130mm | **5mm** |
| 바운스 상한 최악 | 4.6V (VCC 로 잘림) | **0.57V** |
| R16 경고 | 22 | 클럭 버퍼 1개만 (아래) |

남은 것: 74HC244 클럭 버퍼의 바운스 0.58V 가 **클럭 입력**으로 간다 (LOW 여유 1.09V 의 절반 초과).
리드 인덕턴스 10nH 만으로 나오는 값이라 배선으로는 더 못 줄인다. 대책은 클럭선 부하를 줄이거나(짧게),
244 의 두 채널을 나눠 쓰거나(이미 그렇게 함), 실측으로 physics.txt 의 리드값을 확인하는 것.
조합 입력(주소·데이터)으로 가는 바운스는 정착 후 샘플링되므로 타이밍 여유(R7)에 흡수된다 — 정보로만 표시.

## 실행 · 종료

| 하고 싶은 것 | 명령 |
|---|---|
| 켜기 (윈도우) | 바탕화면 `SOL\run.bat` 더블클릭 — 이전 서버가 있으면 먼저 죽이고 시작 |

## 아직 안 한 것

- KiCad 넷리스트는 만들었지만 **KiCad 에서 실제로 열어 보진 못했다**
  (이 환경에 KiCad 없음). 형식은 KiCad 레거시 `(export (version D) ...)`

- 배선 용량 추정 2pF/수신 은 가정값
- 3D 는 cdnjs 의 three.min.js 를 인터넷에서 받는다 — 오프라인이면 캔버스 3D 로 떨어진다 (파일을 옆에 두고 `<script src>` 만 바꾸면 오프라인도 됨)
