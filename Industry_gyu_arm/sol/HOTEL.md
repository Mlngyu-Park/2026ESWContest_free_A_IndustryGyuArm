# HOTEL — KYLE 언어로 만능기판 회로를 짓는 도구 모음

> **KYLE** 은 언어, **HOTEL** 은 그 언어로 설계를 짓고·검증하고·보여 주는 프로그램 전체의 이름이다.
> 규칙 하나: **모든 것은 KYLE 텍스트가 진실이다.** 배치·배선·전원 버스·층·설정·AI 의 예상값까지 전부 `.txt` 한 장에 있고,
> 프로그램은 그 파일을 읽어 검증·배선·3D 로 그릴 뿐이다. 파일을 닫아도 남고, 다시 열면 그대로 재현된다.

## 1. 한눈에

```

   gen_pe2.py ──► pe2.txt ◄──────────────── 뷰어「파일로 저장」/ 텍스트 편집
                    │  KYLE
        ┌───────────┼──────────────┬──────────────────┐
        ▼           ▼              ▼                  ▼
     place.py    sol.py        serve.py / viewer   route_eval.py
     자동 배치   검증 R1~R28   3D·2D·자동배선       실제 배선 채점
     (KYLE→KYLE)   타이밍·전압   (KYLE→그림→KYLE)       (미배선 수 + R28)
```

- **AI 는 `pin REF[핀:넷]` 연결만 쓴다.** 전압·시간·규칙은 sol.py 가 데이터시트 숫자(chips.txt)로 계산한다.
  AI 가 적는 예상값(`expect`)은 툴이 검산할 뿐이다 — 둘이 다르면 데이터시트를 편다. (분리 원칙)

## 4-1. 회로를 실제로 돌린다 (simulate.py)

**AI 는 회로만 짜고, 실행은 HOTEL 이 한다.** 시뮬레이터에는 "이 회로는 곱셈기다" 같은 지식이 한 줄도 없다 —
KYLE 의 `pin`(연결)과 chips.txt 의 `func`/`reg`(칩 동작)만 읽어서 계산한다.

```
python3 simulate.py --selftest                    # 칩 진리표가 데이터시트대로인가 (가산기는 512경우 전수)
python3 simulate.py 설계.txt --jumper JP_CLK=B-C \
    --rom PE0_U1L=mul_lo.bin --rom PE0_U1H=mul_hi.bin \
    --set MEGA.D=7 --net 118=1 --clknet 103 --clock 4 --show PE0_U1L.DQ
```

chips.txt 에 칩의 논리를 적는다 (핀 이름은 데이터시트 그대로):
```
  func 1Y = ~1A                          # 74HC04 인버터
  func 1Y0 = 1A0 & ~1OE#                 # 74HC244 3-state 버퍼
  func c2 = (A1 & B1) | (c1 & (A1 ^ B1)) # 74HC283 자리올림 (cN 은 핀이 아닌 내부 신호)
  reg  Q* D* CP                          # 574 레지스터: 클럭 상승에지에 D→Q
  reg  1Q,1nQ 1D 1CP                     # 74HC74: n 으로 시작하는 출력은 반전
```

**KYLE 안에서 시험을 적는다 (`sim … end`, 2026-09-17):** 회로 파일 자체에 "이 입력을 넣고 클럭을 치면 이 값이 나와야 한다" 를 적으면
`sol.py` 검증(R30)이 실제로 돌려 대조한다. 뷰어「검증 다시 실행」에도 뜬다. 문법은 KYLE.md 의 sim 절.
```
sim     mul7x6
  rom     PE0_U1L mul_lo.bin        # python3 simulate.py --mulrom . 로 만든 곱셈표
  rom     PE0_U1H mul_hi.bin
  jumper  JP_CLK B-C
  in      MEGA.D 7
  pulse   MEGA.WCP0
  in      MEGA.D 6
  clock   MEGA.MCLK 4
  out     PE0_U1L.DQ 42
  out     PE0_U1H.DQ 0
end
python3 simulate.py pe2.txt --run          # 시나리오만 따로 돌리기 → "결과: 전부 일치"
```
pe2.txt / pe1_54x33_2layer.txt 에 mul7x6 · mul255 · mul0 세 시나리오가 들어 있고 R30 정보 6줄(전부 ✔)로 나온다.
잡은 버그: NC(연결 없음) 핀을 네트로 취급해 출력 여럿이 'NC' 값을 두고 다투어 매번 "발진" 으로 보이던 것.

**실측 (2026-09-17):** `pe1_54x33_2layer.txt` 에 w·x 를 넣고 MEGA 클럭을 치면
플래시 곱셈표를 거쳐 **7×6=42, 255×255=65025 까지 20/20 정확**하게 나온다. 클럭 분주기(74HC74)도 2분주로 돈다.

이 과정에서 잡은 것: 핀 이름이 숫자로 시작해(`1A`, `1OE#`) 식 토크나이저가 쪼개던 문제,
74HC283 핀이 A1..A4(1부터)인데 func 를 A0..A3 으로 쓴 것(자체 점검이 512경우 중 511개 틀림으로 잡음),
플립플롭 초기값이 없어 분주기가 영원히 '미정'이던 것, 외부 입력이 settle 에 덮어써지던 것.

## 5. 검증 규칙 (sol.py) — 요약

- R1~R14 연결·전기: 출력끼리 충돌, 미연결 입력, 팬아웃, 레벨(VOH/VIH)·풀업 계산, 전원 전류
- R15 AI 의 `expect` 대 데이터시트 계산 (±0.1V) — **교차검증의 핵심**
- R16~R22 과도현상: 그라운드 바운스 L·di/dt, 디커플링 거리, 크로스토크, 반사, 클럭 스큐, IR 강하, 발열 — **실제 배선 길이로**
- R23 부품 겹침/기판 밖 · R25~R27 층·라이저 · **R28 배선 규칙 전부** (아래)
- 타이밍: 레지스터→레지스터 임계경로 → 최대 클럭 (지금 200ns → 5MHz)

## 6. 배선 규칙 (뷰어 라우터 = R28, 독립 구현 둘)

- 선은 **구멍(납땜점)에서만** 시작·끝·갈라진다. 한 구멍에서 여러 선이 나가는 것(분기)은 핀 구멍이나 관통(바느질) 구멍에서만 — 선 중간(피복 위)에서는 못 갈라진다.
- **협상 재배선**: 처음 깔기 → 실패 네트 놓고 다시(최대 6바퀴) → 그래도 남으면 실패 네트마다 「남의 선·전원 스텁 칸을 비용을 물고 지나는 길」을 찾아 그 길을 막던 네트를 걷어내고 깐 뒤 걷어낸 네트를 다시 깐다. 하나라도 못 돌아오면 통째로 되돌린다 (미배선은 절대 늘지 않는다). 핀·버스 구멍은 절대 못 지난다.
- 전원 버스 줄은 칩·커넥터의 **핀 행 위에 놓지 않는다** (배치기 규칙). 핀 행에 버스가 지나면 그 행의 신호 핀이 갇혀 빈 기판에서도 미배선이 남는다.
- 한 네트의 갈래 하나라도 못 깔면 그 네트는 통째로 '미배선'이고 빨간 고무줄만 보인다 (깔린 반쪽을 남기지 않는다 — 남기면 나중에 다른 선이 그 위를 지나 유령 선이 된다).

**한 면(층×앞/뒤)의 한 칸에는 한 선.** 구멍이든 통로든 같다.
핀 구멍은 그 네트만(앞·뒤 영구) · 핀 접촉은 **뒷면에서만**(앞면 핀 자리는 소켓 아래) · 관통은 빈 구멍에서만 ·
버스 줄의 납땜 구멍은 버스 것(통로로만 직각 횡단) · 전원 스텁도 같은 규칙으로 배선되어 `route VCC auto` 로 쓰인다 ·
비스듬한 선 금지 · 끊긴 끝·안 닿은 핀은 경고.
`share 2·3` 은 사용자가 일부러 켤 때만 구멍에서 색 다른 선 교차 허용 (핀·버스 구멍은 그래도 안 됨).

**미배선** = 이 규칙 안에서 길을 못 찾은 핀-핀 구간. 2D 빨간 점선 / 3D 기판 표면 빨간 점선. 손으로 잇거나(「경로 그리기」) 배치를 바꾼다.

## 7. 자동 배치기 (place.py)

담금질(simulated annealing). 비용 = 네트 반둘레 길이(HPWL) + 혼잡도(RUDY: 네트 상자에 밀도를 얹고 칸 용량 초과의 제곱; 칩 아래는 앞면이 막혀 용량 1)
+ 층을 넘는 네트마다 벌점 + 칩 전원 핀 행 흩어짐 + `near` 힌트 거리.
이동: 옮기기(불법이면 주변 나선에서 합법 자리) / 같은 종류끼리 자리 바꾸기 / 회전 / 층 바꾸기. 합법성: 칩 사이 채널 ≥ 2구멍, 작은 부품 1구멍, 기판 안.
시작 전 **건설식 합법화**: 기판을 비우고 고정 부품 → 큰 칩(넓이순) → 작은 부품 순으로 각자 원래 자리에서 가장 가까운 합법 자리에 다시 놓는다
(불법 쌍은 이동 검사만으로는 절대 안 풀린다). 근처에 없으면 기판 전체·모든 층·양쪽 회전까지 찾고, 그래도 없으면 어느 부품인지 이름을 찍고 멈춘다.
배치 뒤: `near` 캡을 칩 VCC 핀 옆 예약 자리에 · 전원 핀 행을 덮는 최소 버스 행 집합(574·244 처럼 동시 스위칭 8개인 칩은 1행=2.54mm 안, 나머지는 2행) ·
층>1 이면 층을 넘는 네트를 열 기준으로 묶어 두 층 모두 빈 열에 HDR20 라이저(20행 자리가 없으면 HDR8 로 쪼갬).

**층 걸침 보증.** 라이저를 못 얻은 네트가 하나라도 남으면 그 KYLE 은 물리적으로 만들 수 없다(R26 오류). 그래서 마지막에
①라이저가 안 나르는데 층을 걸친 네트를 찾아 ②그 부품들을 다수파 층으로 모으고 ③자리가 없으면 그 층의 작은 부품을 잠시 치워 자리를 내고
④치운 부품을 다시 합법 자리에 놓는다. **진전이 있는 한 계속** 돌고, 정말 안 되면 네트 수를 찍고 멈춘다 (고정 횟수로 끊으면 조용히 틀린 파일이 나온다).
**담금질 비용은 근사, 실제 배선(route_eval)이 심판** — `--search N --route` 로 씨앗 N개 중 미배선 최소를 남긴다.

| place.py 담금질 1회 (씨앗 하나) | 66 ~ 101 | 0 | 씨앗 편차가 크다 |
| place.py `--search 6` (씨앗 6개 중 최고) | **66** | 0 | 씨앗 44 |
| + `--refine 200` (배선을 심판으로 국소 탐색) | **52** | 0 | 66 → 52. 220회 더 돌려도 안 줄어 — 이 방식의 바닥 |
| 44×62 **2층** (`--channel 1`, 5씨앗) | **110** | 0 | 넓이 절반의 대가 |

**완성본 두 가지**
- **`pe1_54x33_2layer.txt`** — 실물 기판용. 54×33 2층, PE 1개, 미배선 37, R28 0. `python3 serve.py pe1_54x33_2layer.txt`
- `pe2_placed.txt` — 큰 기판을 살 경우. 84×62 1층, PE 2개, 미배선 52, R28 0.

**담금질 비용(근사)과 실제 미배선은 잘 안 맞는다.** 씨앗 44 는 비용 7402 로 6개 중 최저였고 미배선도 66 으로 최저였지만,
씨앗 40(비용 8113, 미배선 101)과 42(비용 8114, 미배선 82)처럼 비용이 같아도 미배선은 20 넘게 차이났다.
그래서 `--search` 는 반드시 `--route` 와 같이 쓰고, 마지막은 `--refine` 으로 실제 배선을 보고 다듬는다.

**층(아파트)에 대해 실측한 것.** 층을 올리기만 하면 아무 효과가 없다 — 막히는 칩(래치→플래시 주소선 16가닥)이 같은 층에 남기 때문이다.
라이저를 손으로 세웠더니 헤더가 밀집 지역과 떨어져 오히려 나빠졌다(163~251). 배치기가 ①층 배정(이름 앞 토큰 PE0/PE1 별로 통째로)
②라이저 자리 ③각 층의 버스를 같이 정해야 비로소 배선이 된다. 그래도 84×62 1층(52)이 44×62 2층(116)보다 낫다 —
**층은 "배선이 쉬워지는 수단" 이 아니라 "기판을 반으로 줄이는 대가" 다.** 어느 쪽을 택할지는 실물 만능기판 크기에 달렸다.

## 8-1. 실물 기판 (54×33 구멍 = 137×84mm) — 2026-09-17

사용자의 실제 만능기판. **PE 2개는 한 장에 안 들어간다**: 부품만으로 구멍의 77% (배선 통로까지 치면 55% 넘으면 무리).

| 구성 | 층 | 미배선 | 검증 |
|---|---|---|---|
| PE 2개 | 3층 | 158 | 통과 (씨앗 4개 중 1개만) |
| PE 2개 | 5층 | 217 | 통과 |
| **PE 1개** | 1층 | — | 실패 (U_INV·U_CLK 자리 없음) |
| **PE 1개** | **2층** | **43** | 통과 (씨앗 5개 전부) |
| PE 1개 + 다듬기 200회 (채널 1) | 2층 | 37 | 통과 |
| **PE 1개, 채널 2, 씨앗 탐색 + 다듬기 40회** | **2층** | **30** | 통과, 곱셈 시험(sim) 3개 ✔ — **`pe1_54x33_2layer.txt` = `pe2.txt`** |

**결론: 기판 한 장에 PE 하나, 2층.** PE 2개를 쓰려면 기판 두 장을 핀헤더로 잇는다 (원래 아파트 구조의 취지).
`PES=1 BOARD_W=54 BOARD_H=33 LAYERS=2 python3 gen_pe2.py` → `place.py --board 54 33 --layers 2 --channel 2 --search 6 --route` → `place.py 최고.txt --out 다듬.txt --refine 40` → `route_eval.py 다듬.txt --write pe2.txt`
(채널 2 가 채널 1 보다 나았다: 34 → 다듬기 30. 배선 결과는 파일에 route 로 남겨야 숫자가 재현된다 — 라우터가 핀 순서에 민감해서 같은 배치도 30↔36 이 나온다.)

**층을 올려도 배선은 안 풀린다 (실측).** 같은 84×62 에서 1층 52 → 2층 118 → 3층 115.
이유는 **라이저(층간 핀헤더)가 기판을 먹기 때문**이다 — 54×33 6층에서는 라이저만으로 기판 면적의 98% 를 차지했다.
층으로 번 자리를 층을 잇는 부품이 도로 가져간다. 층은 **부품이 안 들어갈 때만** 쓴다.
(라이저 낭비는 한 번 고쳤다: 여유 핀을 8개씩 붙여 사용률이 29% 였던 것을 실제 수요에 맞춰 87% 로, 개수는 14 → 6개로.)

## 8-2. 기판 여러 장 — 한 장에 PE 하나 (사용자 결정, 2026-09-17)

한 장에 안 들어가면 **장을 나눈다**. 그 구성이 파일에 남아야 다시 열어 이어서 할 수 있다.

```
python3 panelize.py fixture_2pe.txt --out two_boards.txt --by prefix --board 54 33 --layers 2 --channel 2
      (원본은 PE 2개짜리 KYLE 이어야 한다. pe2.txt 는 지금 PE 1개라 그대로 넣으면 B 장이 비어 배선 0 이 나온다 — 2026-09-17 실제로 겪음)
      → panel A / panel B, PE0_* 는 A, PE1_* 는 B, 공통 부품(OSC·클럭·MEGA)은 A, 디커플링 캡은 제 칩 옆 장.
        장을 넘는 네트 42개는 가장자리 HDR8 케이블 6개(link)로. 장마다 place.py 로 따로 배치·라이저·버스.
python3 panelize.py fixture_2pe.txt --out two_boards.txt … --search 4 --refine 30
      → 장마다 씨앗 4개를 실제 배선으로 채점해 최고를 고르고, 배선을 심판으로 30번 다듬는다 (느림, 수십 분).
python3 route_eval.py two_boards.txt          # 장별로 배선해 합산 (2026-09-17 설치본: A:74 · B:48, 장별 R28 위반 0)
python3 serve.py two_boards.txt --panel B     # 뷰어에서 B 장만 열기. 「파일로 저장」은 B 장만 되돌려 넣는다 (A 는 그대로)
```

panelize 가 장마다 채점에 쓴 배선을 `route … panel A` 로 파일에 확정해 넣는다 (라우터는 핀 순서에 민감해 새로 깔면 숫자가 달라진다 — 파일이 진실). `python3 route_eval.py two_boards.txt --write two_boards.txt` 로 다시 깔 수도 있다.

KYLE 문장: `panel A perf 54 33 layers 2` · `part … panel A` · `link L1 HDR8 at A 52 1 to B 1 1`(케이블 양 끝 헤더 L1/L1_B) · `route … panel A` ·
`stack J1A … panel A` · `bus GND rows … panel A`. 검증 **R29**: 장별 기판 밖, 장을 넘는 네트에 link 가 있는지. R23 은 장이 다르면 겹침으로 안 본다.

시험: `python3 test_panel.py` — 나누기 → 검증 → 장별 배선 → 뷰어에서 B 장 열어 부품 옮기고 저장 → A 장 줄이 그대로인지. (2026-09-17 17항목 전부 통과)

## 9. 정직하게 남은 것

- 두 장(two_boards.txt)은 A:74 · B:48 이 남는다. 같은 배치를 같은 씨앗으로 다시 돌리면 76 으로 재현되지만, 한 번(코드 수정 전) A 장이 36 까지 나온 적이 있고 그 원인은 못 찾았다 — 파일에 route 가 들어 있으니 숫자는 파일 기준으로 믿는다.
- 미배선 0 은 아직 아니다. 남는 구간은 뷰어에서 손으로 잇거나, 배치기 씨앗/채널/층을 바꿔 다시 돌린다.
- 44×62 2층은 `--channel 1` 이 필요하다 (채널 2 로는 부품이 안 들어간다). 채널을 줄이면 배선 통로도 줄어드는 맞바꿈이다.
- 빽빽한 2층에서는 씨앗마다 결과 편차가 크다 — `--search` 로 여러 개 돌리고 검증을 통과한 것만 고른다 (검증 실패는 자동으로 탈락).
- `--refine` 은 한 번 평가에 2~4초(실제 배선)라 200회면 10분 남짓이다. 오래 돌릴수록 줄지만 수확은 점점 준다 (66→52 에 150회).
- KiCad 변환은 배치까지다 (구리 트랙 없음). 만능기판 바느질 배선과 PCB 트랙은 규칙이 달라 그대로 옮기면 틀린다.
- **`place.py` 를 고칠 때 집합(set) 순회를 새로 넣지 말 것.** 파이썬은 프로세스마다 문자열 해시를 무작위화해서,
  네트 이름 집합을 그냥 돌면 같은 씨앗인데도 결과가 매번 달라진다 (2층 기판에서 R26 오류가 간헐적으로 남았던 원인).
  네트·부품 이름을 도는 곳은 `sorted()` 를 쓴다. 확인법: 같은 명령을 두 번 돌려 출력 파일 해시가 같은지 본다.
- 3D 「보는 층」은 그 층의 선·저항·캡·핀만 보인다 (2026-09-17 고침: 전엔 다른 층 선이 공중에 떠 보였다). 「전부」면 층을 겹쳐 그린다.
- 3D 는 스크린샷으로 직접 보고 판단할 것 — 숫자 검사가 통과해도 화면이 틀린 적이 세 번 있었다 (`feedback_verify_visually`).
