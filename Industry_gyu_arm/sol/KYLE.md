> **KYLE** — 이 언어의 이름 (예전 이름: SOL). 파일 확장자·도구 이름(sol.py)은 그대로 둔다.

# KYLE — 납땜 설계 언어

만능기판 손납땜 회로를 글로 적는 언어. (예전 이름 SOL = Solder On Logic)
확장자는 `.txt`. 사람이 읽고, 프로그램이 검증하고, KiCad 로 넘긴다.

---

## 0. 핵심 원칙 — 포인터 표기

```
PE0_U2[19:5]      PE0_U2 의 19번 다리는 네트 5
PE0_U1L[27:5]     PE0_U1L 의 27번 다리도 네트 5   → 둘은 연결됨
```

**다리에 번호표를 붙인다.** 같은 번호끼리 연결이다.
선을 "A 에서 B 로" 저장하지 않는다. 그래서 **칩을 옮겨도 연결은 그대로**다.

AI 는 `pin`(연결)과 `expect`(전압 **예상**)만 쓴다. 계산은 하지 않는다 —
그건 프로그램이 `chips.txt` 숫자로 한다. 예상과 계산이 다르면(R15) 데이터시트를 연다.

## 1. 파일 구조

```
#KYLE 1                         ← 첫 줄. 버전
title   PE 2개 새 모양
board   perf 61 55             ← 만능기판 구멍 수 (가로 세로), 2.54mm 격자
include chips.txt              ← 부품 라이브러리

supply  VCC 5.0V max 5A        ← 전원. 여기서 전압이 출발한다
supply  GND 0V

part    PE0_U2  74HC574  at 10 2          ← 부품 놓기. (열,행) = 1번 핀 구멍
part    PE0_U1L SST39SF040 at 15 2 rot 0  ← rot 0/90/180/270

pin     PE0_U2[19:5]           ← 포인터. 19번 다리 = 네트 5
pin     PE0_U2[20:VCC]         ← 네트는 숫자 또는 이름(VCC, GND)
pin     PE0_U2[1:GND]

group   5  w→ROM               ← 네트에 그룹 이름 (색·납땜 순서용)
color   w→ROM  #d62728         ← 그룹 색

route   5 front PE0_U2.19 (12,3) (14,3) PE0_U1L.27   ← 손으로 그린 경로 (선택)
route   5 back  ...            ← 뒷면 경로
route   101 auto back (2,15) (2,15.5) (0.5,15.5) | (0.5,24) (2,24)   ← ★ 자동배선도 KYLE 문장이다
        ↑ auto = 뷰어 자동배선이 쓴 것(「배선 다시」가 지우고 새로 씀) · .5 = 구멍 사이 통로 · | = 그 구멍을 관통(바느질)
        ↑ layer N 을 붙이면 그 층. 전원 스텁(핀→버스 줄)도 route VCC auto … 로 쓴다
wire    0.5mm                  ← 배선 굵기 (물리 값이라 UI 가 아니라 KYLE 문장)
stitch  6                      ← 바느질 간격 (칸)
share   1                      ← 점당 선 수 (1 = 겹침 없음. 2·3 은 구멍에서 색 다른 선 교차 허용 — 사용자가 일부러 켤 때만)

expect  5   4.4 0.1            ← AI 의 전압 예상: 네트 5 는 HIGH 4.4V / LOW 0.1V
expect  202 4.9 0.4 1.06mA     ← LOW 일 때 흡수 전류까지
expect  VCC 5.0                ← 전원은 한 값

bus     GND rows 11,19,24,34,45  ← GND 버스 선이 가로로 지나는 행. 각 GND 핀은 가장 가까운 버스에 짧게
bus     VCC rows 1,12,25,35      ← (없으면 기판 위/아래 레일 하나로 보고 R16 이 경고한다)

board   perf 44 62 layers 3      ← ★ 아파트 구조: 기판을 3층으로 쌓는다
part    PE1_U2 74HC574 at 12 2 layer 2     ← 이 부품은 2층
stack   J1 HDR20 at 7 38 layers 1-2        ← 1층↔2층 연결 핀헤더 (여러 장이면 `panel A` 를 붙인다)
panel   A perf 54 33 layers 2              ← ★ 기판 여러 장: 장마다 한 줄. part 에 `panel A` 로 소속
link    L1 HDR8 at A 52 1 to B 1 1         ← ★ 장간 케이블: A 장 (52,1) 헤더 ↔ B 장 (1,1) 헤더.
                                              파서가 두 헤더(L1, L1_B)를 부품으로 세우고, pin L1[k:넷] 은 둘 다에 적용
stack   J4 HDR8  at 1  1 layers 2-3        ← 2층↔3층 (★ 중간층은 위·아래가 서로 다른 칸을 쓴다)
pin     J1[1:VCC]                          ← 그 헤더의 1번 핀이 나르는 네트
```

`#` 뒤는 주석. 빈 줄 무시. 들여쓰기 무의미.

### expect — AI 가 "이럴 것이다" 를 적는 자리

AI 는 배선(`pin`)을 하면서 **각 네트가 몇 볼트일지 자기 예상을 `expect` 로 적는다.**
프로그램은 그 줄을 보지 않고 `chips.txt` 로 따로 계산한 뒤 **R15 에서 대조**한다.

| 프로그램이 계산하는 것 | 근거 |
|---|---|
| HIGH 보장 범위 = [드라이버 VOH(min), VCC] | 데이터시트 VOH |
| 풀업이 있으면 HIGH(min) = VCC − R×누설 | 수신 1µA/입력 + 3상태 누설 10µA |
| LOW 보장 범위 = [0, 드라이버 VOL(max)] | 데이터시트 VOL |
| 수신 여유 = VOH − max(VIH), min(VIL) − VOL | 수신 칩 VIH/VIL |
| LOW 흡수 전류 = ΣV/R (풀업) | 옴의 법칙, 드라이버 IOL 과 비교 (R13) |

AI 예상이 보장 범위 밖이면(±0.1V) **R15 경고**. 예상 HIGH 가 수신 VIH 보다 낮으면 그것도 경고.
전체 표는 `python3 sol.py pe2.txt --volt` → `pe2_volt.txt`.

### sim — 회로를 실제로 돌려 보는 시험 (입력 → 클럭 → 기대 출력)

```
sim     mul7x6                     # 시나리오 이름
  rom     PE0_U1L mul_lo.bin       # 플래시 내용 (설계 파일 기준 상대경로). 없으면 out 대조를 건너뛰고 경고
  rom     PE0_U1H mul_hi.bin
  jumper  JP_CLK B-C               # 실물 점퍼(shunt) 를 꽂은 상태
  in      MEGA.D 7                 # 버스 입력: D0..D7 핀에 7 을 (접두어 뒤 숫자가 비트)
  pulse   MEGA.WCP0                # 핀 하나를 0→1→0 (레지스터 클럭 한 번)
  in      MEGA.D 6
  clock   MEGA.MCLK 4              # 클럭 핀을 4번 (0→1 상승에지 4번)
  out     PE0_U1L.DQ 42            # 기대값. 다르면 R30 오류
  out     PE0_U1H.DQ 0
  show    PE0_U2.Q                 # 값을 보여주기만 (정보)
end
```

`in`/`out`/`show` 의 대상은 `부품.핀이름`(핀 하나), `부품.접두어`(접두어0..N 을 묶은 버스), 또는 그냥 네트 이름(`in 118 1`).
값은 10진 또는 `0x2A`. **simulate.py 가 `pin` 연결과 chips.txt 의 `func`/`reg` 만으로 실제로 계산**하고, sol.py **R30** 이
`out` 과 대조한다 — AI 는 관여하지 않는다(시뮬레이터에 회로 지식 0줄). 뷰어「검증 다시 실행」에도 R30 결과가 뜬다.
`python3 simulate.py 설계.txt --run` 으로 따로 돌릴 수 있고, `--mulrom 폴더` 가 곱셈표 ROM(mul_lo/hi.bin) 을 만든다.

## 2. 부품 라이브러리 `chips.txt`

**모든 숫자에 출처(문서·쪽)를 적는다.** 사람이 정한 값이 아니라 제조사 값이다.

```
chip 74HC574 DIP20
  src   "Nexperia 74HC_HCT574 Rev.10 (2024-08-05)"
  pin 1   OE#  in  ctrl
  pin 2   D0   in  data
  ...
  pin 10  GND  gnd
  pin 11  CP   clk
  pin 12  Q7   out
  pin 20  VCC  vcc
  level HC                       # VIH 3.15V VIL 1.35V @4.5V  p5
  vih 3.15  vil 1.35  voh 4.4  vol 0.1
  cin  3.5pF                     # p5
  icc  80uA                      # p5 quiescent max 25°C
  t clk2q 33ns                   # p8 CP→Qn max 25°C @4.5V CL=50pF
  t setup 12ns                   # p8
  t hold   5ns                   # p8
```

핀 종류:

| 종류 | 뜻 |
|---|---|
| `in` | 입력. 아무 데도 안 붙으면 **플로팅 경고** |
| `out` | 출력. 같은 네트에 둘이면 **충돌 치명** |
| `clk` | 클럭 입력. 타이밍 분석의 기준점 |
| `bi` | 양방향 (플래시 DQ, 커넥터) |
| `vcc` `gnd` | 전원. 전원 네트에 안 붙으면 오류 |
| `pas` | 수동 (커패시터, 핀헤더). 검사 안 함 |
| `nc` | 미연결 허용 |

조합 회로 지연은 `path` 로:
```
  path A*   S*   42ns    # An/Bn → Sn  p9 max @4.5V
  path CIN  COUT 39ns
```
`*` 는 와일드카드. 레지스터는 `clk2q`·`setup` 만 쓴다.

## 3. 프로그램이 하는 검사

| # | 규칙 | 등급 |
|---|---|---|
| R1 | 핀 번호가 패키지 밖 | 오류 |
| R2 | 한 네트에 VCC 와 GND | **치명** |
| R3 | 한 네트에 `out` 둘 이상 | **치명** |
| R4 | `in`/`clk` 인데 네트 없음 (플로팅) | 경고 |
| R5 | `vcc`/`gnd` 핀이 전원 네트 아님 | 오류 |
| R6 | 출력 하나가 미는 입력 용량 합 > 50pF | 경고 (지연 규격 밖) |
| R7 | 레지스터→레지스터 최장 경로 → 최대 클럭 | 정보 |
| R8 | 전원 전류 합 > `supply max` | 경고 |
| R9 | 플래시 WE# 가 VCC 아님 | 경고 (오작동 지우기) |
| R10 | 네트에 드라이버 없음 (입력만 모임) | 경고 |
| R11 | 드라이버 VOH(min) < 수신 VIH(min) — **레벨 불일치** | 경고 |
| R12 | 칩 수 > 0.1µF 수 | 경고 (디커플링) |
| R13 | 풀업 흡수 전류 > 드라이버 IOL | 경고 |
| R14 | 풀업 RC (능동 구동 시 참고) | 정보 |
| **R15** | **AI 의 `expect` 전압이 계산된 보장 범위 밖** | 경고 — 교차검증의 핵심 |
| R16 | **그라운드 바운스** V = L·di/dt (리드 + 접지선 인덕턴스, 동시 스위칭 출력 수, 부하 C, 에지) vs LOW 여유 | 경고 + 대책 수치 |
| R17 | 디커플링 거리 → 스위칭 순간 VCC 처짐 (L·di/dt + Q/C) | 경고 |
| R18 | 배선 크로스토크 (평행 구간 상호인덕턴스 M·di/dt) | 경고 |
| R19 | 반사: 최장 배선 vs 임계 길이 tr/(2·전파지연) | 정보 |
| R20 | 클럭 스큐: 배선 길이차 × 6.7ps/mm vs hold | 정보 |
| R21 | 전원 레일 IR 강하 | 정보 |
| R22 | 발열 P·θJA | 경고 |
| R23 | 부품 겹침 / 기판 밖 (같은 층끼리만 비교) | 오류 |
| R25 | 층 번호가 `board layers` 범위 밖 | 오류 |
| R26 | 네트가 여러 층에 걸쳤는데 `stack` 을 안 지남 | 오류 |
| R27 | `stack` 이 이웃하지 않은 층을 이음 | 경고 |
| R29 | 여러 장(panel): 부품이 제 장 안에 있나, 장을 넘는 네트가 `link` 헤더를 지나나 (안 지나면 물리적으로 연결 불가) | 오류 |
| R28 | **모든 `route`(손·자동·전원 스텁) 배선 규칙** — 한 면 한 칸 한 선 / 남의 핀 구멍 / 앞면 부품 아래 / 핀 접촉은 뒷면만 / 관통은 빈 구멍 / 버스 구멍 / 비스듬 / 끊긴 끝·안 닿은 핀. **뷰어 라우터와 독립 구현** → 교차검증 | 오류·경고 |

R16~R22 는 **SPICE 가 아니다.** 교과서 공식과 `physics.txt` 의 경험 상수(리드 10nH, 선 1nH/mm 등 — 출처 명시)로
**크기의 자릿수**를 보는 것이다. 전부 상한(최악)으로 계산하고 VCC 를 넘지 않게 자른다.
실측(오실로스코프)하면 `physics.txt` 값을 갱신한다.

R11 이 중요하다. TTL 출력(2.4V)이 CMOS 입력(3.15V)에 들어가면 **규격상 보장이 안 된다.**

## 5. 아파트 구조 (다층 기판)

기판을 옆으로 넓히는 대신 **위로 쌓는다.** 층 사이는 핀헤더(수/암)로 잇는다.

```
3층 ─── J4 (HDR8, 2-3층)
2층 ─┬─ J1 J2 J3 (1-2층)
1층 ─┘
```

- **중간층은 위·아래 각각 자기 칸**을 쓴다. 2층에서 1-2층용 헤더와 2-3층용 헤더가
  같은 구멍을 쓰면 못 꽂으므로, 생성기가 빈 자리를 찾아 서로 다른 열에 세운다.
- 층이 달라도 **회로는 같다.** 전압(R15)은 네트 기준이라 안 바뀌고,
  접지선이 층을 타면 길어지므로 **R16(그라운드 바운스)만 다시 계산**된다.
- 3D 소켓은 실물 DIP 소켓(높이 3.6mm, 두 줄 레일 + 양 끝 다리, 가운데 뚫림, 1번 홈). 「칩 뽑아 올리기」로 칩을 들어 소켓 접점을 본다.
- 뷰어의 「기판」 패널에서 가로·세로·층수를 바꾸면 3D 가 층을 쌓아 그리고,
  「보는 층」으로 한 층만 떼어 볼 수 있다.

만드는 법: `LAYERS=2 BOARD_W=44 BOARD_H=62 python3 gen_pe2.py`

## 5-1. 배선 규칙 (뷰어 자동배선이 지키는 것)

**한 면(층×앞/뒤)의 한 칸에는 한 선.** 구멍이든 구멍 사이 통로든 똑같다. 다른 네트가 있는 칸엔 못 들어간다.
그래서 같은 면에서 선이 교차하는 일은 없다 — 셀 점유 검사와 순수 기하(선분 교차) 검사 두 가지로 확인한다.

| 상황 | 규칙 | 이유 |
|---|---|---|
| 핀 구멍 | 그 핀의 네트만, 앞·뒤 모두 영구 예약 | 남이 먼저 지나가면 주인이 못 들어온다 |
| 선이 핀에 닿는 면 | **뒷면(납땜면)만** | 앞면의 핀 자리는 소켓·부품 몸통 아래라 납땜할 수 없다. 핀 구멍에서 관통도 안 한다 |
| 미배선 표시 | 2D: 빨간 점선 / 3D: 기판 위 8mm 에 뜬 빨간 고무줄(양면에서 보임) | 선이 아니라 '아직 못 이은 곳'. 예전엔 3D 에서 보통 선처럼 그려져 가짜 교차로 보였다 |
| 전원 버스 줄 (뒷면 맨 구리선) | 납땜 **구멍**은 전부 버스 것. 구멍 사이 **통로**는 신호가 직각으로 넘어갈 수 있다 | 절연선이 맨 구리선 위를 지나는 건 만능기판 표준 관행. 납땜점 위는 안 됨 |
| 전원 스텁 (핀→버스 짧은 선) | 통째로 막는다 | 절연선끼리 겹치는 것이라 안 된다 |
| 관통(바느질) 구멍 | 그 네트가 앞·뒤 모두 차지 | 반대면에서 남이 납땜점 위를 지나면 안 된다 |
| 앞면 한 선 + 뒷면 한 선, 같은 구멍 | 허용 | 기판이 갈라놓는다. 둘 다 납땜 안 된 채 지나가는 것 |
| 「점당 2·3」 (기본은 1) | 켜면 **구멍에서만** 색 다른 선끼리 교차 허용 | 사용자가 일부러 켠 경우만. 미배선은 줄지만 납땜점에서 선이 겹친다 |

**배선은 파일이 진실이다.** 「파일로 저장」이 자동배선까지 `route … auto` 로 쓰고, `bus`·`expect`·설정 문장도 함께 쓴다.
파일만 있으면 배선이 그대로 재현되고, `python3 sol.py` 의 R28 이 뷰어와 다른 구현으로 같은 규칙을 검사한다
(둘이 일치해야 믿는다 — 2026-09-16 실측: 뷰어 720구간 → R28 위반 0). R16(접지선)·R19(반사)도 실제 경로 길이로 계산된다.

미배선(빨간 점선)은 이 규칙 안에서 길을 못 찾은 구간이다. 「경로 그리기」로 손으로 잇거나, 칩을 옮기거나,
그 자리만 점당 2 로 타협한다. 「배선 다시」는 배선 순서를 바꿔 5번 시도해 가장 좋은 것(미배선↓ 꺾임↓ 길이↓)을 남긴다.

**여러 장의 route:** `route NET [auto] SIDE [layer N] panel A (c,r) …` — 경로가 놓인 장을 적는다. R28 은 장마다 따로 검사한다(장이 다르면 같은 좌표라도 다른 기판). 장 표시 없는 route 는 한 장 파일에서만 쓴다.

## 6. KiCad 로 내보내기 (PCB 변환)

```
python3 sol.py pe2.txt --kicad
  → pe2.kicad.net    넷리스트만 (Pcbnew ▸ File ▸ Import Netlist)
  → pe2.kicad_pcb    ★ 배치까지 들어간 기판 파일 (그냥 열면 됨)
```

넷리스트만 넣으면 KiCad 가 부품을 한 구석에 무더기로 쌓아놓고 배치를 손으로 다시 해야 한다.
KYLE 은 이미 `at col row` · `rot` · `layer` 를 갖고 있으므로 `.kicad_pcb` 쪽이 그 배치를 그대로 옮긴다.

- 구멍 좌표 × 2.54mm = KiCad mm 좌표. 1번 핀은 사각 패드.
- 층이 여러 개면 **층마다 (기판폭+10mm) 씩 X 로 떨어뜨려** 한 장에 나란히 놓고 `1층/2층/3층` 글씨를 찍는다.
- 패드는 전부 thru_hole ⌀0.9 / 1.7mm — 만능기판과 같은 규격.
- `KICAD_FP` 에 없는 패키지가 나오면 **조용히 넘어가지 않고 멈춘다** (엉뚱한 풋프린트로 기판이 나가는 걸 막는다).

## 7. 왜 이렇게 만들었나

- **포인터 표기**: 칩 자리를 바꿔도 다리가 안 헷갈린다
- **출처 명시**: "공식이 맞나"를 사람한테 안 묻는다. 문서를 연다
- **AI 분리**: AI 는 `pin` 과 `expect`(예상) 만 쓴다. 계산값을 적을 수 없고, 예상은 프로그램이 검산한다
- **txt**: 어떤 편집기로도 열린다. git 으로 차이를 본다
